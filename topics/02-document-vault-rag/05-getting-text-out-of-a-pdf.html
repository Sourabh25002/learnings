Lesson 5

Getting text out of a PDF

Before anything can be searched, the PDF has to become plain text. In the Vault this is done by extractPdfPageWise in services/documentOcr.py, using free Python libraries. It works for digital PDFs and silently fails on scanned ones.

Why a PDF isn't like a .txt file

.txt file

Contains exactly what you see, in reading order. If it shows Hello, the file holds those 5 letters.

.pdf file

Contains drawing instructions, often compressed:

use font Arial, size 12
draw "Amount:" at (300, 120)
draw "Account" at (50, 40)
draw "50000"   at (380, 120)
draw a line from here to here

A PDF viewer reads these instructions and draws the page for you. What you see is the result, not the file's contents. (Open a PDF in VS Code to see: obj, stream, /Font and lots of gibberish.)

A .txt file is a letter: you just read it. A PDF is a blueprint: someone has to build the page before you can see it.

So a library extracting text has to rebuild it: work out which words are on the same line, the reading order, where spaces go, and how to handle columns, tables, headers and footers. That's where extraction goes wrong sometimes. For us it's one line of code; the library does the hard part.

Digital vs scanned PDFs

KindHow it was madeText stored inside?
Digital PDFExported from software: bank statements, broker contract notes, Word → PDFYes. Every word, with its position
Scanned PDFA scan or photo of paperNo. Each page is just an image

The Vault assumes digital PDFs. It reads text that's already stored in the file. Tables are text too in a digital PDF; they're not images.

OCR and Textract

OCR = Optical Character Recognition: reading text from an image by recognising letter shapes. Optical (it looks), Character (letters, numbers, symbols), Recognition (works out what they are). Everyday examples: Google Lens, phone document scanners, apps reading a credit card number through the camera.

AWS Textract is Amazon's OCR service in the cloud. You send a PDF or image and get text back. It also understands layout: tables as rows and columns, form fields as "label: value" pairs, even handwriting. It's paid per page.

Watch out: "OCR" in the code isn't OCR

The code, comments and logs say "OCR" everywhere ("Running OCR on...", documentOcr.py). The team used Textract earlier, then switched to free libraries, and the names stayed. Textract code still exists (in documentOcr.py, rag/textractOcr.py and the textract/ folder) but nothing calls it. In an interview, say "we extract text with pdfplumber", not "we run OCR".

We don't need to know how these libraries read a PDF internally, the same way we use axios without knowing how HTTP works underneath. What matters is: which one does what, what goes in and out, the limits, and our own rules on top.

extractPdfPageWise, step by step

Inputs: pdfPath, password (always "" from the Vault), fromApi (output format; the Vault passes True), progressCallback (None), returnPerPage (False).

  1. Password check (PyMuPDF) Locked with no password → error "This PDF is password protected...". Wrong password → "Invalid password." Right password → save an unlocked copy to a temp file, because Camelot and pdfplumber handle passwords badly.
  2. Find tables (Camelot, two scans) "Lattice" finds tables with grid lines; kept if Camelot is at least 70% confident. "Stream" finds tables aligned by spacing only; kept at 60%+. Results are grouped by page, each with its position on the page.
  3. Remove duplicate tables If a stream table overlaps a lattice table by over 50%, it's the same table; the lattice one is kept.
  4. For each page (pdfplumber) Read the text. If it contains "annexure a", skip the whole page. Collect the page's tables (dropping ones with 2 or fewer columns). Read the text again (same result). Save it labelled: "\n--- Page 3 ---\n" + text.
  5. Return With fromApi=True: (list of page texts, list of tables). Other formats exist for other callers (all pages joined into one string, or per-page dictionaries for /ocr).

Camelot's confidence score

For every table, Camelot reports an accuracy score (0–100): how cleanly the text fit into the rows and columns it detected. Camelot returns everything; the 70/60 filter is the team's choice. Too high misses real but messy tables; too low keeps junk (addresses or two-column paragraphs mistaken for tables). Stream is given a lower bar because line-less tables naturally score lower. There's no official right number: you test on real PDFs and pick one that separates real tables from junk.

A worked example

A one-page bank statement, as a person sees it:

┌─────────────────────────────────────────┐
│          HDFC BANK - Account Statement  │
│  Name: Sourabh Kumar                    │
│  Account No: 50100123456                │
│  ┌──────────┬───────────────┬─────────┐ │
│  │ Date     │ Description   │ Amount  │ │
│  │ 01-09-26 │ Salary        │ 50,000  │ │
│  │ 05-09-26 │ Rent          │ -15,000 │ │
│  └──────────┴───────────────┴─────────┘ │
│  Closing Balance: 35,000                │
└─────────────────────────────────────────┘

What comes out:

file_ = [
  "\n--- Page 1 ---\nHDFC BANK - Account Statement\nName: Sourabh Kumar\nAccount No: 50100123456\nDate Description Amount\n01-09-26 Salary 50,000\n05-09-26 Rent -15,000\nClosing Balance: 35,000"
]
tables = [ ...the table as rows... ]    # found, never used by the Vault

A list with one item per page. The table's words survive, but as plain lines with spaces: the boxes and columns are gone.

Back in the worker

pages = [{"pageNumber": i + 1, "content": text} for i, text in enumerate(file_)]
successfulPages = [p for p in pages if p.get("content", "").strip()]
if not successfulPages:
    raise ValueError("OCR returned no content from any page.")
  1. Number the pages: [{"pageNumber": 1, "content": "..."}]. Keeping page numbers is how chat can later say "found on page 1".
  2. Keep only pages with text.
  3. If none are left, fail the file.
  4. Log "✓ OCR complete: 1/1 page(s) extracted successfully."

This list goes to indexDocument (Lesson 6).

There's also an if holdingType == "pms" branch that calls localOcr instead. It never runs in the Vault, because holdingType is never fetched. It was copied in from the same pattern used in /ocr and docVaultLlm.getDocumentSummary.

How asset-holdings uploads differ

The asset-holdings upload (POST /upload_pdf_nocron in routes/fileRoutes.py) extracts transactions a completely different way: it turns every page into an image and sends the images to Gemini with document-specific instructions (PMS, AIF, contract note, dividend statement). PDFs over 5 pages are queued for later.

The old text-plus-tables method for holdings is commented out, so right now nobody uses Camelot's tables. They're leftover work.

Limits and bugs

PDF typeWhat happens
All textAll text extracted
Text + images (logo, chart, a screenshot of a table)Text extracted; anything inside images is silently lost
Fully scannedNothing real extracted, yet marked "completed" (see below)
Bugs found here
  • Scanned PDFs are marked "completed". Every page gets the label --- Page N ---, even when its text is empty. So "empty" pages never look empty, the "no content" check never triggers, and the file is indexed as chunks containing only labels. Chat then says "couldn't find that" with no hint the file was unreadable.
  • Page numbers shift. Pages with "Annexure A" are skipped, but page numbers are assigned by position in the list. Skip page 3 and the real page 4 is labelled "page 3"; chat references point to the wrong page.
  • Unlocked copies are never deleted. Each password-protected PDF leaves an unlocked copy on the server's disk: a privacy and disk-space problem. (Not hit by the Vault today, since the password is always empty.)
  • Wasted work. Camelot scans every page twice, the slowest part, and the Vault throws the result away. Each page's text is also extracted twice.
  • 2-column tables dropped. The comment says single-column tables are ignored; the code drops 2-column ones (like Name | Value) too.
  • "Annexure A" pages are always skipped, which looks like a rule copied from the loan-form feature. A Vault user asking about Annexure A gets nothing.
