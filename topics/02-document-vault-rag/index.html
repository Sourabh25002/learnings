Chapter 2

Document Vault (RAG)

The Document Vault lets users upload their PDFs and ask questions about them in plain language. Behind it is a RAG pipeline: upload, background processing, text extraction, chunking, embeddings and a vector database, then search and an AI-written answer. This chapter follows one file through all of it.

What this chapter is (and isn't)

It's a study of the real Doc Vault code in the pythoncode repo: what each part does, why it's built that way, and every gap found along the way. The ideas (RAG, chunking, embeddings, vector search) apply to any stack, including Node.js. Lessons are written as each part is studied; dashed cards aren't written yet.

Glossary

RAG
Retrieval-Augmented Generation: find the relevant pieces of your documents, then give only those to the AI along with the question.
Chunk
A small piece of a document's text (here, up to 1,000 characters). The unit that gets searched.
Overlap
The part each chunk shares with the previous one (here, 200 characters), so sentences cut at a boundary still appear whole somewhere.
Embedding
A list of numbers representing a text's meaning. Similar meanings give similar numbers.
Vector
A list of numbers. An embedding is a vector.
Vector database
A database that finds stored items whose vectors are closest to a given vector, i.e. search by meaning.
ChromaDB
The vector database used here. Stored as files in a folder, like SQLite. One per document.
Collection
A ChromaDB "table". Ours is called financial_documents.
Metadata
The label attached to each chunk: file name, page number, chunk position, text or table.
docName
A document's unique ID in the RAG system: its S3 file name without folder or extension, e.g. 42_1760345678123.
indexS3Key
The S3 folder where a document's ChromaDB index is backed up, e.g. vaultFile/42_1760345678123/.
Digital PDF
A PDF made by software, with its text stored inside. What the Vault supports.
Scanned PDF
A PDF where each page is an image (a scan or photo). Has no stored text.
OCR
Optical Character Recognition: reading text from an image by recognising letter shapes.
AWS Textract
Amazon's paid OCR service. Its code exists in the repo but isn't used.
pdfplumber
The Python library that reads the text out of each PDF page in the Vault.
Camelot
A Python library that finds tables in PDFs, with a confidence score per table.
PyMuPDF (fitz)
A fast PDF library. Used here to open PDFs and handle passwords.
FastEmbed
The library that runs the embedding model locally on our server.
Blueprint
Flask's version of express.Router().
Decorator
A line starting with @ above a function that adds behaviour to it, e.g. registering a route or checking auth.
Docstring
A function's description in triple quotes, as its first line. Like a JSDoc comment.
Cron
Linux's built-in scheduler. Runs the worker every 5 minutes here.
supervisord
A process manager (like pm2) that runs gunicorn and cron side by side in one container.
gunicorn
The production web server that runs the Flask app.
Lock file
A file whose existence means "a run is in progress", so overlapping cron runs exit.
Stale lock
A lock left behind by a crashed run. Here, any lock older than 2 hours.
Quota
Each user's lifetime upload limit: 100MB, tracked in the userFileQuota table.
