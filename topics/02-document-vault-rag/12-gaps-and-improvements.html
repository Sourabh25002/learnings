Lesson 12

Known gaps and improvements

Every gap found while studying the Vault, in one place, with how serious it is and how to fix it. These are good first tickets: small, real fixes that are easy to explain. Chat-side gaps will be added after Lessons 9–11.

In this lesson

  4. Wasted work and cleanup
  5. Good first tickets
Before changing anything

Show the list to the team lead first. Some of these depend on decisions that aren't visible in the code (for example, how the vaultFiles table's unique key is defined, or whether the Vault was ever meant to support PMS-specific extraction).

Security

GapWhereFix
Upload into someone else's account. Uses the userId sent by the frontend, not the one from the login token.vaultRoutes.py /uploadUse g.userId
No server-side file checks. PDF-only, size and page limits are frontend-only./uploadCheck type, size and pages in the route; set Flask's MAX_CONTENT_LENGTH
Hard-coded fallback internal key. Missing INTERNAL_API_KEY falls back to a key in the source code.core/config.pyRefuse to start without the key
Unlocked PDF copies left on disk.extractPdfPageWiseDelete the temp copy in a finally

Correctness

GapWhereFix
Scanned PDFs marked "completed". The --- Page N --- label means empty pages never look empty.processFile + extractPdfPageWiseCheck the text without the label; mark scanned files as an error with a clear message (or fall back to OCR)
Wrong page numbers after an "Annexure A" page is skipped.processFileReturn real page numbers from extraction
0 chunks still "completed".processFileTreat 0 chunks as an error
Fallback embedding model has a different size (384 vs 768).getEmbeddingModelRemove the fallback, or store which model indexed each document
Password-protected PDFs always fail; holdingType never used.pending-files querySelect the columns, or remove the dead branches
"Annexure A" pages always skipped, a rule copied from the loan form.extractPdfPageWiseMake the skip optional; off for the Vault

Reliability

GapWhereFix
Half-finished multi-file uploads; quota not counted for files that did upload./uploadCount usage per file; report which files succeeded
Re-upload with the same name orphans the old PDF and index in S3.addVaultFileDelete the old S3 objects when a row is overwritten
S3 succeeds, DB fails → orphan PDF./uploadDelete the S3 object if the insert fails
Same-millisecond S3 names overwrite each other./uploadAdd a UUID to the name
Failed status updates ignored → files re-processed.processFileRetry the update, or log loudly
"No pending files" hides connection errors.apiGetPendingReturn None on error and log it differently
Concurrent uploads can beat the quota.fileQuota.pyAtomic check-and-increment in one SQL statement

Wasted work and cleanup

  • Camelot scans every page twice; the Vault throws the tables away. Skip it on the Vault path. This is the biggest speed win.
  • Each page's text is extracted twice.
  • Local ChromaDB folders are never deleted after upload.
  • userName required but unused (left behind by my quota change).
  • Old pipeline files: rag/chunker.py, embedder.py, vectorStore.py, retriever.py, textractOcr.py.
  • Outdated docstrings (Textract, non-existent command-line options); the misleading processBatch default of 5.
  • indexS3Key built by hand in the worker instead of returned by indexDocument.

Good first tickets

Small, safe and easy to explain in an interview:

  • Bind /upload to g.userId (security)
  • Server-side file validation on /upload (security)
  • Fix the scanned-PDF "completed" bug (correctness, visible to users)
  • Remove the userName check (follow-up to my quota work)
  • Skip Camelot on the Vault path (speed)
  • UUID in S3 names (reliability)
