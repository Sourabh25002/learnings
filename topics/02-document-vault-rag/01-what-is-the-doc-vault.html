Lesson 1

What is the Document Vault?

The Document Vault lets a user upload their PDFs (bank statements, contract notes, reports) and then ask questions about them in plain language: "What is my closing balance?", "When was the last dividend paid?". This lesson is the map for the whole chapter.

What the user sees

  1. Upload The user picks one or more PDFs on the Vault page and uploads them. The reply comes back in a second or two: "Upload complete. Files will be processed in background."
  2. Wait The file shows as pending, then processing, then completed. This can take a few minutes.
  3. Chat Once a file is completed, the user can ask questions. The answer comes with references: which file and which page it came from.

The two halves

The Doc Vault does two jobs: prepare the file once (in the background), then answer questions from it as many times as the user likes.

Part 1: prepare the file

  1. The user uploads a PDF. It's saved to S3, and a database row is created with status pending.
  2. A background worker picks it up (within 5 minutes).
  3. It extracts the text, page by page.
  4. It cuts the text into small pieces (chunking).
  5. It turns each piece into numbers that capture its meaning (embedding) and saves them in a small database (ChromaDB), backed up to S3.
  6. The file is marked completed.

Part 2: answer questions

  1. The user asks a question about their files.
  2. The system finds the pieces of the files most related to the question.
  3. It sends those pieces plus the question to Gemini (Google's AI).
  4. Gemini answers using only that information.
  5. The user sees the answer, with the file name and page it came from.

What "RAG" means

RAG = Retrieval-Augmented Generation. Split into its three words:

  • Retrieval: find the relevant pieces of the user's documents.
  • Augmented: add those pieces to the question.
  • Generation: the AI writes the answer from them.

An open-book exam. The AI doesn't need to have memorised your bank statement. Before each question, someone finds the right page in your book and puts it in front of the AI. The AI just reads that page and answers.

Why not just send the whole PDF to the AI?

For one small PDF, you could. It stops working well as soon as documents get bigger or more numerous:

ProblemWhy RAG helps
Size limitsAI models can only read so much text at once. A user with 20 long statements would go over the limit. RAG sends only a few small pieces.
CostYou pay per amount of text sent. Sending 5 small pieces is far cheaper than sending 20 whole PDFs on every question.
SpeedLess text in, faster answer out.
AccuracyWith a mountain of text, the AI is more likely to miss or mix up details. With only the relevant pieces, it stays focused.
ReferencesEach piece carries its file name and page number, so the answer can say where it came from.

The life of one file

Every uploaded file is one row in the vaultFiles database table. Its status column moves like this:

pending  ──►  processing  ──►  completed     (ready for chat)
                         └──►  error         (reason saved in errorMessage)
StatusSet byMeaning
pendingThe upload routeSaved to S3, waiting for the worker
processingThe worker, when it starts on the fileBeing extracted and indexed right now
completedThe worker, at the endSearchable. Chat is allowed
errorThe worker, if anything failedNot searchable. The reason is in errorMessage

Chat refuses any file that isn't completed.

Which files do what

All of this lives in the pythoncode repo.

The two most important files are rag/indexer.py (turns a document into something searchable) and rag/ragEngine.py (searches it and generates the answer).

Files you can ignore

Watch out: old code that looks important

The rag/ folder contains five files from an older version of the pipeline (February 2026). The pipeline was rebuilt in June 2026, and nothing calls these anymore. They have convincing names, so they're easy to study by mistake.

  • rag/chunker.py: old chunking. The real chunking is inside rag/indexer.py.
  • rag/embedder.py: old embedding. indexer.py loads the model itself.
  • rag/vectorStore.py and rag/retriever.py: old search.
  • rag/textractOcr.py: old AWS Textract extraction.
