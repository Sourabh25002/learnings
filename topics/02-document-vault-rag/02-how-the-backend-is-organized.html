How the backend is organized

The Python backend is a Flask app. Flask is very close to Express, so if you know Node.js you already know most of it. This lesson maps every Flask idea you'll meet in the Vault code to its Node.js equivalent.

Route and controller are one function here

In Node you'd usually have routes/vault.js and controllers/vaultController.js. Here, each route function also contains the controller logic: read the request, check things, call services, send the response. Heavy work (S3, quota, AI) is still pulled out into services/ and rag/. 

Node:   route → controller → service → database
Here:   route + controller (one function) → service → database

The starting point

main.py is the app.js. Its createApp() function:

  1. Creates the Flask app.
  2. Sets up CORS, with allowed origins from config.
  3. Registers 5 route files: stockRoutes, fileRoutes, chatRoutes, vaultRoutes, portfolioRoutes.
  4. Adds a global error handler.
  5. Adds cleanup that closes the MySQL connection pool on shutdown.
// Express                         # Flask (main.py)
const app = express();             app = Flask(__name__)
app.use(cors());                   CORS(app, ...)
app.use(vaultRoutes);              app.register_blueprint(vaultRoutes)
app.listen(8000);                  serve(app, port=8000)

Locally you run python main.py. In production, the server loads wsgi.py, which is just from main import app.

Routes, Blueprints and decorators

A Blueprint is Flask's express.Router(). Each file in routes/ creates one and adds endpoints to it.

@vaultRoutes.route("/upload", methods=["POST"])   # 1. register the endpoint
@requireAuth                                      # 2. middleware: check the login token
def upload():                                     # 3. the handler
    ...

Lines starting with @ are decorators: they attach extra behaviour to the function below. A request goes through them top to bottom: route match → auth check → your function. The same thing in Express: 

router.post("/upload", requireAuth, upload);

Docstrings

Text in triple quotes as the first line inside a function ("""Fast upload: ...""") is a docstring: the function's description, like a JSDoc comment. Python doesn't run it. Editors show it when you hover the function name.

Docstrings can be out of date

Several docstrings in the Vault code describe older versions (Textract, command-line options that don't exist). When a docstring and the code disagree, trust the code.

One request, start to finish

Say the frontend calls POST /vault_llm_chat:

  1. main.pyThe app receives the request.
  2. vaultRoutes.pyThe URL matches /vault_llm_chat.
  3. @requireAuthThe middleware in core/middleware.py checks the JWT. It looks in the JSON body (auth_token), the form data, then the Authorization header. On success it stores the user's ID as g.userId.
  4. The route functionReads userId and query, checks in the database that the file is ready.
  5. The servicevaultChat() in services/docVaultLlm.py does the AI work.
  6. The responseThe route sends the answer back as JSON.

Every endpoint follows the same path: route → middleware → handler → service → database / S3 / AI → response.

How it runs in production

One Docker container runs two programs side by side, managed by supervisord (like pm2):

One Docker container
└── supervisord   (starts both, restarts either if it crashes)
      ├── gunicorn   → the web server (all the API routes), port 8080
      └── cron       → every 5 minutes runs processVaultFiles.py (the worker)

Lesson 4 explains the worker and why it's a separate program.

Tip: rebuild it to really learn it

Every idea here (upload, background worker, chunking, embeddings, vector search) is the same in any language. Rebuilding the Vault in Node.js as a personal project is a great way to make sure you understand it, and that project is fully yours.
