Section 4 · Lesson 21

Similarity and Semantic Search

Embeddings and cosine similarity together: first score how similar sentences are, then build a small semantic search, the same kind of search a vector database runs. 

import numpy as np
from langchain_openai import OpenAIEmbeddings

def cosine_similarity(vec1, vec2):
    dot_product = np.dot(vec1, vec2)
    norm_a = np.linalg.norm(vec1)
    norm_b = np.linalg.norm(vec2)
    return dot_product / (norm_a * norm_b)

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

The cosine function from Lesson 18 and OpenAI's cheapest model.

Example 1: how similar are these sentences?

sentences = [
    "The cat sat on the mat",
    "A feline rested on the rug",
    "The dog played in the yard",
    "I love programming in Python",
    "Python is my favorite programming language",
]

sentence_embeddings = embeddings.embed_documents(sentences)   # one vector per sentence

# Calculate similarity between all pairs
for i in range(len(sentences)):
    for j in range(i + 1, len(sentences)):
        similarity = cosine_similarity(sentence_embeddings[i], sentence_embeddings[j])
        print(f"'{sentences[i]}' vs '{sentences[j]}'")
        print(f"Similarity: {similarity:.3f}\n")

Example 2: semantic search

Semantic search: given a query and some documents, return the documents closest in meaning, best first.

documents = [
    "LangChain is a framework for developing applications powered by language models",
    "Python is a high-level programming language",
    "Machine learning is a subset of artificial intelligence",
    "Embeddings convert text into numerical vectors",
    "The weather today is sunny and warm",
]

query = "What is LangChain?"
def semantic_search(query, documents, embedding_model, top_k=3):
    """Simple semantic search implementation"""
    # Embed the query and the documents
    query_embedding = embedding_model.embed_query(query)
    doc_embeddings = embedding_model.embed_documents(documents)

    # Calculate similarities
    similarities = []
    for i, doc_embedding in enumerate(doc_embeddings):
        similarity = cosine_similarity(query_embedding, doc_embedding)
        similarities.append((similarity, documents[i]))

    # Sort by similarity, highest first, and return the top k
    similarities.sort(reverse=True)
    return similarities[:top_k]

Embed the query and every document, score each document against the query, sort highest first, keep the top k.

results = semantic_search(query, documents, embeddings)
for score, doc in results:
    print(f"[{score:.3f}] {doc}")

"What is LangChain?"

0.676: "LangChain is a framework for developing applications powered by language models". The rest score far lower.

"What is embeddings?"

0.662: "Embeddings convert text into numerical vectors", then machine learning, then LangChain.

The right document wins both times, though neither query appears word for word.

How this relates to a vector database

A vector database does exactly this. But comparing the query with every stored vector gets slow with millions of chunks, so vector databases use special indexes to find the nearest vectors quickly without checking them all (nearest-neighbour search). That's what the next section uses.

Takeaways

  • Cosine similarity on embeddings measures meaning, even with different words.
  • Semantic search: embed query and documents → score → sort → top k.
  • Vector databases do the same, at scale, with fast nearest-neighbour indexes.
