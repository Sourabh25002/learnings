Section 2 · Lesson 6

Query Processing and Generation

With the vector database filled, two components remain: handling the user's question (query processing) and writing the answer (generation).

Query processing

The vector database holds information about RAG, and the user asks "What is RAG?"

  1. Take the query"What is RAG?"
  2. Embed it The query goes through an embedding model and becomes a vector, like [0.3, 0.4, 0.6, …]. It must be the same model used for the chunks, so the query's numbers and the chunks' numbers are comparable.
  3. SearchFind the chunks whose vectors are closest to the query's, using similarity search (cosine similarity, Euclidean distance).
  4. Retrieved resultsThe best-matching chunks (document 1, 2, 3…) become the LLM's context.
  5. AugmentThe chunks are enriched with metadata, which makes the context, and so the answer, more accurate.

What reaches the LLM

PartExample
Original query"What is RAG?"
Retrieved chunksDocuments 1, 2, 3
Augmented contextThose chunks plus their metadata

Generation

The original query and the enriched context go to an LLM, which writes a summarised answer in natural language and returns it to the user.

Any LLM can do this step: OpenAI models, open-source models like Llama via Groq, or Google Gemini.

The whole pipeline

ComponentWhen it runsWhat it does
IngestionOnce, in advanceLoad, split, embed, store
Query processingEvery questionEmbed the query, search, augment
GenerationEvery questionLLM answers from the context

The rest of the course implements each part, starting with ingestion: reading and parsing every kind of data source.

Takeaways

  • Query processing: embed the question with the same model, search for the closest chunks, augment them.
  • Generation: query + context go to the LLM, which answers in plain language.
