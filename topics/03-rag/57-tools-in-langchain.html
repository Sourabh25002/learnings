Section 11 · Lesson 57

Tools in LangChain

A tool is a function the model can ask to run (fetch data, search the web, run code): a schema (name, description, arguments) plus the function or coroutine to execute.

Creating a tool

from langchain.tools import tool

@tool
def get_weather(location: str) -> str:
    """Get the weather at a location."""
    return f"It's sunny in {location}."

The @tool decorator turns the function into a tool, taking its schema from the name, arguments and docstring. The body could call a real API.

Letting the model request it

model_with_tools = model.bind_tools([get_weather])

response = model_with_tools.invoke("What's the weather like in Boston?")
print(response)

for tool_call in response.tool_calls:
    print(tool_call["name"], tool_call["args"])
# get_weather {'location': 'Boston'}

bind_tools tells the model the tool exists. Qwen3 (a reasoning model) reasons "I need to use the get_weather function" and returns a tool call: get_weather(location="Boston").

A tool call is only a request

Nothing has run yet: the response contains the request, not the weather or an answer.

The tool execution loop

# 1. The user's message
messages = [{"role": "user", "content": "What's the weather in Boston?"}]

# 2. The model replies with a tool call
ai_msg = model_with_tools.invoke(messages)
messages.append(ai_msg)

# 3. Run each requested tool and add its result
for tool_call in ai_msg.tool_calls:
    tool_result = get_weather.invoke(tool_call)
    messages.append(tool_result)

# 4. The model answers using the tool's result
final_response = model_with_tools.invoke(messages)
print(final_response.text)    # "The weather in Boston is sunny."

Two model calls: one to choose the tool, one to answer from its result. get_weather.invoke(tool_call) runs the tool and returns a tool message, which is appended to the history before the second call.

Takeaways

  • @tool + a clear docstring; bind_tools lets the model request it.
  • Loop: invoke → run tool calls → append results → invoke again.
