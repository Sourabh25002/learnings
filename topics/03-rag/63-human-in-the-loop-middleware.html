Section 11 · Lesson 63

Human-in-the-Loop Middleware

Agents act on their own, which is risky for payments, database writes or compliance steps. Human-in-the-loop middleware pauses the agent before chosen tool calls until a person approves, edits or rejects them.

An agent that buys stocks: one wrong trade loses real money, so it asks you to confirm every purchase first.

Setup

from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command
from langchain_core.messages import HumanMessage
from langchain.tools import tool

@tool
def read_email_tool(email_id: str) -> str:
    """Read an email by its ID."""
    return f"Email content for ID: {email_id}"

@tool
def send_email_tool(recipient: str, subject: str, body: str) -> str:
    """Send an email (mock function)."""
    return f"Email sent to {recipient} with subject '{subject}'"
agent = create_agent(
    model="gpt-4o",
    tools=[read_email_tool, send_email_tool],
    checkpointer=InMemorySaver(),
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "send_email_tool": {"allowed_decisions": ["approve", "edit", "reject"]},
                "read_email_tool": False,
            }
        ),
    ],
)

Sending email pauses for a decision; reading email (False) runs freely. A checkpointer is required: pausing means saving the agent's state so it can resume exactly where it stopped.

Approve

config = {"configurable": {"thread_id": "test-approve"}}

result = agent.invoke(
    {"messages": [HumanMessage("Send email to john@test.com with subject 'Hello' and body 'How are you?'")]},
    config,
)
result["__interrupt__"]        # the paused send_email_tool call, waiting for a decision

if "__interrupt__" in result:
    print("Paused! Approving...")
    result = agent.invoke(
        Command(resume={"decisions": [{"type": "approve"}]}),
        config,
    )

print(result["messages"][-1].content)
# "The email has been sent to john@test.com with the subject 'Hello'."

The first call stops with __interrupt__ instead of an answer. Command(resume=...), with the same thread ID, resumes it with the decision; the email is sent and the agent confirms.

Reject

config = {"configurable": {"thread_id": "test-reject"}}
result = agent.invoke({"messages": [HumanMessage("Send email to ...")]}, config)

if "__interrupt__" in result:
    result = agent.invoke(
        Command(resume={"decisions": [{"type": "reject"}]}),
        config,
    )
# The messages record that the user rejected the tool call;
# the agent replies that there was an issue sending the email.

The email is never sent; the agent is told the call was rejected.

Edit

config = {"configurable": {"thread_id": "test-edit"}}
result = agent.invoke(
    {"messages": [HumanMessage("Send email to wrong@email.com with subject 'Test' and body 'Hello'")]},
    config,
)

if "__interrupt__" in result:
    result = agent.invoke(
        Command(resume={"decisions": [{
            "type": "edit",
            "edited_action": {
                "name": "send_email_tool",
                "args": {
                    "recipient": "correct@email.com",
                    "subject": "Test",
                    "body": "Hello (edited by human before sending)",
                },
            },
        }]}),
        config,
    )
# Tool message: "Email sent to correct@email.com ..."

edited_action replaces the agent's call with corrected arguments: the email goes to correct@email.com.

More built-ins

Model call limits (per thread or run, against infinite loops) and a tool selector (filters irrelevant tools to save tokens), each configurable.

Takeaways

  • interrupt_on picks which tools need a human.
  • Paused → __interrupt__; resume with Command(resume={"decisions": [...]}).
  • Needs a checkpointer and the same thread ID.
