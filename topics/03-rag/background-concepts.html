AI basics

Generative AI

AI that creates new content (text, images, code, audio) instead of just sorting or labelling existing data. ChatGPT writing an email is generative AI; a spam filter marking an email as spam is not.

Deep learning

A branch of machine learning that uses large neural networks: many layers of simple maths units that learn patterns by being shown huge amounts of examples. Embedding models and LLMs are both deep learning models.

LLM (Large Language Model)

An AI model trained on a huge amount of text so it can understand and write language. At its core it does one thing: given some text, predict the next piece of text, over and over. That's enough for it to answer questions, summarise, write code and chat.

  • Large because it has billions of parameters and was trained on a big chunk of the internet, books and code.
  • It only knows what was in its training data, up to the date that data ends. That gap is exactly what RAG fills.
  • Examples: GPT-4 (OpenAI), Gemini (Google), Llama (Meta), Claude (Anthropic).

Transformer

The model design (architecture) almost every modern LLM is built on, introduced by Google researchers in the 2017 paper "Attention Is All You Need". Its key idea, attention, lets the model look at all the words in a text at once and work out which ones matter for each other (e.g. that "it" in a sentence refers to "the bank"). That made models much better at understanding context and much faster to train, which is what made today's LLMs possible. The "T" in GPT stands for Transformer.

Parameters (weights)

The numbers inside a model that it learned during training. Everything the model "knows" is stored in them. "Llama 3 8B" means the model has about 8 billion parameters. Training and fine-tuning change these numbers; prompting and RAG don't touch them.

Token

The unit of text an LLM reads and writes. A token is usually a word or part of a word: "unbelievable" might be split into "un", "believ", "able". As a rough guide, 100 tokens is about 75 English words.

  • Token limit / context window is the maximum number of tokens a model can handle at once (your input plus its output). This is why RAG sends a few relevant chunks instead of whole documents.
  • API pricing is usually per token, so fewer tokens means cheaper calls.
  • Each model family has its own way of splitting text into tokens (its tokenizer). tiktoken is OpenAI's tokenizer library, used to count tokens the way their models do.

Agentic AI and agentic RAG

A normal LLM call is one step: question in, answer out. An agent is an LLM that can decide what to do next: pick a tool, call it, look at the result, and decide whether to do something else, looping until the task is done.

Normal (traditional) RAG

Always retrieves once, then answers. Fixed steps.

Agentic RAG

The agent decides whether to retrieve, which source to search, rewrites the query if the results are poor, and may retrieve several times before answering.

From Section 10 on, the course draws a sharper line: an AI agent is a single program doing one specific task, while agentic AI is a system of several agents collaborating towards a larger goal (Lesson 53).

LangChain, LangGraph, LangSmith

LangChain

LangChain is a Python library that gives you ready-made building blocks for every step of an LLM app, so you don't have to write the plumbing yourself.

RAG stepWithout LangChainLangChain gives you
Read filesSeparate code for PDF, Word, CSV, web…Document loaders, all returning the same Document shape
ChunkYour own splitting logicText splitters
EmbedEach provider's own APIOne embeddings interface
Store and searchEach vector database's own APIOne vector store interface
GenerateEach LLM provider's own APIOne chat model interface

You can do every step yourself with plain Python. LangChain just makes it shorter, and lets you swap pieces (FAISS → Pinecone, OpenAI → Groq) with a one-line change. For example, reading and chunking a PDF:

On your own

from pypdf import PdfReader

reader = PdfReader("policy.pdf")
chunks = []
for n, page in enumerate(reader.pages):
    text = page.extract_text()
    for i in range(0, len(text), 800):
        chunks.append({
            "text": text[i:i + 1000],
            "source": "policy.pdf",
            "page": n + 1,
        })

With LangChain

from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter

docs = PyPDFLoader("policy.pdf").load()
splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000, chunk_overlap=200)
chunks = splitter.split_documents(docs)

Is it still the standard? It's the most widely used framework of its kind, but not the only one: LlamaIndex is the main alternative (strong for RAG), and many production teams skip frameworks and call the LLM and vector database SDKs directly. The RAG steps you learn are the same either way.

Version note

The course uses LangChain v0.3. LangChain 1.0 was released in late 2025. The core ideas are the same, but some import paths moved, e.g. text splitters now come from langchain_text_splitters. If course code fails on a newer install, check the version first.

LangGraph

A library from the same team for building multi-step and agent workflows. You draw the workflow as a graph: steps are nodes, arrows decide what runs next, and it can loop (e.g. "retrieve → check if results are good → if not, rewrite the query and retrieve again"). It's the usual tool for agentic RAG.

LangSmith

A web dashboard from the same team for seeing what happened inside each run of your app: which chunks were retrieved, what prompt went to the LLM, how long each step took, what it cost. Used for debugging and evaluating quality.

Fine-tuning terms

LoRA and QLoRA

Cheaper ways to fine-tune. Instead of changing all of a model's billions of parameters, LoRA (Low-Rank Adaptation) freezes them and trains a small set of extra numbers added on top. QLoRA does the same on a compressed ("quantized") copy of the model, so it fits on a smaller GPU.

GPU

A graphics processor, a chip that does thousands of calculations in parallel. Training and running large models needs this kind of parallel maths, so GPUs are the main cost of fine-tuning. Companies usually rent them from cloud providers by the hour.

Other terms

NLP (Natural Language Processing)

The field of AI about getting computers to work with human language: understanding, translating, summarising. Turning words and sentences into vectors (embeddings) is an idea that came from NLP, and LLMs are its biggest result.

JSON sits in between and is often called semi-structured: it has fields, but they can nest and vary.

JSON

JavaScript Object Notation: the standard text format for sending data between programs, and what most APIs return. It's made of key–value pairs in { } and lists in [ ], which can nest inside each other: 

{"name": "Asha", "skills": ["Python", "SQL"], "manager": {"name": "Ravi"}}

A related format, JSON Lines (.jsonl), puts one JSON object per line. It's common for logs and event streams, since new lines can be appended without rewriting the file.

jq

pandas and DataFrames

pandas is the standard Python library for working with tables. A DataFrame is its table object: rows and named columns, like a sheet in Excel held in memory. pd.read_csv() and pd.read_excel() load files into DataFrames; df.iterrows() walks through the rows one by one.

NumPy and Matplotlib

NumPy is the standard Python library for maths on lists of numbers (arrays), which makes it a natural fit for vectors. np.dot(a, b) computes a dot product and np.linalg.norm(a) a vector's magnitude. Matplotlib is the standard Python plotting library; plt.scatter draws points and plt.annotate labels them.

Dense vector

A vector where (almost) every number carries some value, like the 384 numbers an embedding model outputs. The opposite is a sparse vector: very long and mostly zeros, e.g. one slot per word in the vocabulary with a count only for the words that appear. Embeddings are dense, which is why they can capture meaning in relatively few numbers.

Clustering

Grouping items so that similar ones end up together, without being told the groups in advance. With embeddings, that means grouping texts whose vectors are close, like the cat/kitten, dog/puppy and car/truck groups in Lesson 18.

Euclidean (L2) distance

The straight-line distance between two points, as with a ruler. For vectors: subtract them number by number, square each difference, add them up, take the square root. Small distance = the vectors are close = similar meaning. Unlike cosine similarity, which only looks at the angle between vectors, Euclidean distance also notices differences in length.

Chroma's default l2 score is actually the squared distance (it skips the square root). For vectors of length 1, which is what OpenAI's embeddings are, it's tied directly to cosine similarity: L2² = 2 − 2 × cosine. So a Chroma score of 0.23 corresponds to a cosine similarity of about 0.885, and the two always rank results in the same order.

Shortening embeddings (the dimensions parameter)

OpenAI's text-embedding-3 models were trained so that the most important information sits in the first numbers of each vector. Passing dimensions=1024 asks the API to return a shorter vector (1,024 instead of 1,536 for 3-small) that keeps most of the quality. Shorter vectors take less storage and search faster. The catch: every vector in one index must have the same length, so the number must match what the vector database was set up with, and you must use the same setting when embedding documents and queries.

PCA and dimensionality reduction

Dimensionality reduction means turning vectors with many numbers into vectors with fewer, while keeping as much of the important information as possible. PCA (principal component analysis) is the classic way to do it: it finds the few directions along which the data varies most and keeps only those. Reduce 1,500-dimensional embeddings to 2 and you can plot them; words that were close in 1,500 dimensions mostly stay close in 2.

SQL databases, SQLite and JOINs

A SQL database stores data in tables (rows and columns) and is queried with the SQL language (SELECT … FROM … WHERE …). Examples: PostgreSQL, MySQL, and SQLite, a tiny SQL database that lives in a single file with no server, which makes it handy for learning.

  • Primary key: the column that uniquely identifies each row (usually id).
  • Foreign key: a column that points to another table's primary key, linking the two (like projects.lead_id → employees.id).
  • JOIN: a query that combines rows from linked tables. An inner join keeps only rows that match in both; a left join keeps every row from the first table even without a match.
  • DDL: Data Definition Language, the statements that define tables (CREATE TABLE …).

NoSQL databases (like MongoDB) don't use fixed tables; they store flexible, JSON-like documents instead.

API

A way for one program to talk to another. You send a request (e.g. "search the web for today's AI news" or "embed this text") and get a response back. When the course says an LLM uses a web search API, the LLM's app is sending requests to a search service.

API key

A secret string that identifies you to a paid service like OpenAI. You send it with every API request so the provider knows whose account to bill and that you're allowed to use it. Keep it private (e.g. in an environment variable, not in your code).

.env files and environment variables

An environment variable is a named value the operating system hands to a running program, e.g. OPENAI_API_KEY. Libraries like LangChain's OpenAI integration read the key from there, so it never has to be written in the code. A .env file is a plain text file of NAME="value" lines kept in the project folder (and left out of git, so the secret isn't shared). load_dotenv() from python-dotenv reads it and puts each value into os.environ, unless a variable of that name already exists. So in most cases the course's extra os.environ[...] = os.getenv(...) line just reassigns a value that's already set; it does no harm.

KNN (k-nearest neighbours)

A classic machine learning idea: to decide about a new point, look at the k stored points closest to it (e.g. k = 3). In vector search, "closest" means highest similarity (or smallest distance) to the query vector, so "find the k nearest neighbours" just means "return the top k matches". Checking every stored vector is exact but slow on huge collections; libraries like FAISS use clever indexes to find approximately the nearest ones much faster.

CRUD

Short for Create, Read, Update, Delete: the four basic things you can do with records in a database. A vector database lets you add new vectors, fetch them, change them (or their metadata) and remove them, like any other database.

Distributed systems: replication, sharding, high availability, scaling

  • Distributed system: one database spread across several machines (servers) that work together.
  • Replication: keeping copies of the same data on several machines, so nothing is lost if one fails.
  • Sharding: splitting the data into parts (shards), each stored on a different machine, so no single machine has to hold everything.
  • High availability: the system stays up even when some machines go down, thanks to those copies.
  • Vertical scaling: giving one machine more power (CPU, RAM). Horizontal scaling: adding more machines.

Full-text search

Classic keyword search: find documents that contain the words you typed (like a search box on a website), usually with smart ranking and handling of word forms. It matches words, while vector search matches meaning. Some databases, Chroma included, offer both.

Temperature and max_tokens

An LLM writes its answer one token at a time, each time choosing from many possible next tokens. Temperature controls how adventurous that choice is: near 0 it almost always picks the most likely token, giving focused, repeatable answers; higher values (around 1) pick less likely tokens more often, giving more varied, creative text. Low values like 0.2 suit RAG, where answers should stick to the context. max_tokens caps how long the answer can be; generation stops once the limit is reached.

Chat messages: system, human, AI

Chat models take a conversation as a list of messages, each with a role. A system message sets the rules ("you are an assistant for question-answering…"). Human messages are what the user says. AI messages are the model's replies; in LangChain, llm.invoke(...) returns an AIMessage, whose .content is the reply text.

Runnables and the pipe operator

In LangChain, almost everything (prompts, models, retrievers, output parsers) is a runnable: an object with an invoke method that takes an input and returns an output. a | b creates a new runnable that runs a, then feeds its output into b. A plain function like format_docs placed in a chain is wrapped automatically (as a RunnableLambda). A dictionary at the start of a chain is turned into a RunnableParallel: each value receives the same input and they run side by side, producing a dictionary of results, which is how {"context": ..., "question": ...} builds the prompt's inputs.

Reading model names: gemma2-9b-it

Open model names pack in a lot: gemma2 is the model family and version (Google's Gemma 2), 9b means about 9 billion parameters (bigger is usually smarter but slower), and it means instruction-tuned: trained further to follow instructions and chat, rather than just continue text. You'll see the same pattern in names like llama-3.1-8b-instruct.

Pickle and deserialization

Pickle is Python's built-in way to save Python objects to a file (serialization) and load them back (deserialization). FAISS's save_local writes two files: index.faiss (the vector index) and index.pkl (the documents and metadata, pickled). The catch: loading a pickle file can run code hidden inside it, so a malicious file could do anything on your machine. That's why LangChain makes you pass allow_dangerous_deserialization=True: you're confirming the file is one you trust, such as one you created yourself.

Streaming (token streaming)

An LLM generates its answer one token at a time. Normally (invoke) you wait until the whole answer is finished and get it all at once. With streaming (stream), each token or small group of tokens is sent to you as soon as it's generated, so the text appears word by word, the way ChatGPT types out its replies. The total time is about the same, but the user sees the answer start almost immediately, which feels much faster in a chat app.

Apache Cassandra

An open-source, distributed database originally built at Facebook, designed to spread huge amounts of data across many servers with no single point of failure (see distributed systems). DataStax builds its products, including Astra DB, on top of it.

Serverless

A way of running a cloud service where you don't pick or manage any servers: the provider runs and scales the machines for you, and you typically pay for what you use (requests, storage) rather than for machines sitting idle. A "serverless vector database" is one you just create and call; the provider handles the rest. You still choose a cloud (e.g. AWS) and a region (the geographic data centre, e.g. us-east-1), ideally close to where your app runs.

Regular expressions (regex)

A mini-language for describing patterns in text, used to find, match or split on them. For example, the pattern (?<=[.!?])\s+ means "the spaces right after a full stop, exclamation or question mark", so re.split with it breaks text into sentences. Python's built-in re module handles regular expressions.

scikit-learn (sklearn)

The standard Python library for classic machine learning: models, data preparation and evaluation tools. It also has handy helpers such as sklearn.metrics.pairwise.cosine_similarity, which takes two lists of vectors and returns a matrix of the cosine similarity between every pair.

Python classes, __init__ and self

A class is a blueprint for objects that bundle data and functions together. chunker = ThresholdSemanticChunker(threshold=0.7) creates one object (an instance) from the blueprint. __init__ is the constructor: it runs once when the object is created and usually stores settings. self is the object itself, so self.threshold = threshold saves the value on that object, and every method can read it later. Functions defined inside a class are called methods and are called on the object: chunker.split_documents(docs).

How LangChain's SemanticChunker decides where to split

SemanticChunker doesn't use a fixed similarity like 0.7. By default it:

  1. Splits the text into sentences with a regex that breaks after ., ? or !.
  2. Embeds each sentence together with its neighbours (buffer_size=1: one sentence on each side), which smooths out very short sentences.
  3. Computes the cosine distance (1 − similarity) between each pair of neighbouring sentences.
  4. Splits wherever the distance is unusually large. With the default breakpoint_threshold_type="percentile" and amount 95, "unusually large" means larger than 95% of the distances in that document.

So the threshold adapts to each document. Other options for breakpoint_threshold_type are "standard_deviation", "interquartile" and "gradient", and you can change the amount, e.g. SemanticChunker(embedding, breakpoint_threshold_type="percentile", breakpoint_threshold_amount=90) to split more often.

Bag of words, TF-IDF and BM25

Three classic ways to turn text into a sparse vector for keyword matching:

  • Bag of words: one slot per word in the vocabulary; the value is whether (or how often) the word appears. Word order is ignored.
  • TF-IDF (term frequency × inverse document frequency): like bag of words, but each word is weighted. TF rises the more often the word appears in this document; IDF is high for words that appear in few documents and low for common words like "the". So rare, specific words ("Pinecone", "BM25") count for much more than everyday ones.
  • BM25: an improved TF-IDF used by most search engines. Repeating a word gives diminishing returns (the 10th "LLM" adds far less than the 2nd), and long documents don't win just by being long.

One practical detail when mixing these with cosine similarity: BM25 scores aren't limited to 0–1 (they can be 5, 12, …), while cosine scores are. Real hybrid systems therefore normalise both scores to the same range (or combine rankings instead of raw scores) before applying the α weighting.

Reciprocal Rank Fusion (RRF)

A simple way to merge ranked lists from different searches without comparing their raw scores. Each document gets 1 / (k + rank) from every list it appears in (rank 1 is the top result; k is a constant, commonly 60), and the contributions are added up. Documents ranked high by several searches rise to the top. LangChain's EnsembleRetriever uses a weighted version: each list's contributions are multiplied by that retriever's weight (e.g. 0.7 and 0.3). Because only ranks are used, it doesn't matter that BM25 scores and cosine scores are on different scales.

Recall, precision, hit rate and coverage

Ways to judge what a retriever returns. Recall: of all the documents that are actually relevant to a question, what fraction did the search return? (Finding 3 of 4 relevant chunks = 75% recall.) Precision: of the documents the search returned, what fraction are actually relevant? (3 relevant out of 5 returned = 60% precision.) Hit rate: across many test questions, how often was at least one correct document among the results? Coverage is a looser idea: do the results cover the different aspects of the question, or just one aspect many times?

Hybrid search mainly raises recall (it misses less). Reranking helps the most relevant results come first. MMR trades a little precision for more coverage.

Bi-encoders vs cross-encoders

The embedding models used for retrieval are bi-encoders: they turn the query and each document into vectors separately, so document vectors can be computed once, stored, and compared very quickly. The price is that the model never sees the query and the document side by side.

A cross-encoder takes the query and one document together as a single input and outputs a relevance score. Because it can compare every word of the question with every word of the document, it judges relevance much more accurately. But nothing can be precomputed, and it must run once per (query, document) pair, which is far too slow for millions of documents. Hence the two-stage design: a bi-encoder (or BM25) quickly narrows millions down to the top 10–50, then a cross-encoder reranks just those. Popular open-source rerankers include cross-encoder/ms-marco-MiniLM-L-6-v2 and the BGE reranker models; Cohere offers one as an API.

CrewAI

An open-source Python framework for building agentic AI applications as a "crew" of agents. Each agent gets a role (e.g. researcher, writer), a goal and tools, and the agents work through tasks together. It's often mentioned alongside LangChain and LangGraph as a way to build multi-agent systems.

Multi-hop reasoning

Answering a question that needs several facts chained together, where each step depends on the one before. "Who founded the company that makes the iPhone, and where was that person born?" needs two hops: Apple → Steve Jobs, then Steve Jobs → San Francisco. A single retrieval often can't find both facts at once; breaking the question into steps lets each hop get its own retrieval.

Zero-shot

Doing a task without any task-specific examples or training. "Zero-shot retrieval" means retrieving well on a new collection of documents without first training or fine-tuning a retriever on labelled examples from that collection. HyDE was designed for this: it relies on a general-purpose LLM and embedding model, with no relevance labels.

CLIP, Vision Transformers and shared embedding spaces

CLIP has two encoders: a text Transformer for text and a Vision Transformer (ViT) for images. A ViT cuts an image into small square patches (32 × 32 pixels in clip-vit-base-patch32, hence the name), treats each patch like a word, and processes the sequence with a Transformer.

Contrastive training is what links the two. CLIP was shown hundreds of millions of (image, caption) pairs and trained so that each image's vector is pulled close to its own caption's vector and pushed away from all the other captions. After training, both encoders output vectors in one shared space: the text "a photo of a dog" and an actual dog photo end up near each other. That's what lets a text query retrieve an image with ordinary cosine similarity.

Base64 and data URLs

Base64 is a way to write any binary data (like the bytes of a PNG image) using only plain text characters (letters, digits, + and /). It makes files about a third bigger, but they can then travel inside text formats like JSON. A data URL puts that text straight into a URL: data:image/png;base64,iVBORw0KGgo…. Multimodal LLM APIs accept images this way, so no image hosting is needed.

PyTorch and tensors

PyTorch (torch) is the deep learning library most Hugging Face models run on. It works with tensors: multi-dimensional arrays of numbers, like NumPy arrays but able to run on GPUs. torch.no_grad() tells PyTorch you're only using the model, not training it, so it skips the bookkeeping needed for training, which saves memory and time.

Reinforcement learning

A kind of machine learning where a system learns by trial and error: it takes actions, receives a reward or penalty for the outcome, and gradually favours the actions that earn more reward. A smart home agent might be "rewarded" for saving electricity and "penalised" when a person comes home to a cold house, and over time learn when to turn the heating on.

Agile, sprints and stories

Agile is a common way of running software projects in short cycles instead of one long plan. Work is split into small stories (tasks, each describing one piece of functionality), and the team commits to a set of them for a sprint, typically one or two weeks. At the end of each sprint the work is built, tested and reviewed, and the next sprint is planned from what was learned. CI/CD (continuous integration / continuous deployment) automates building, testing and releasing the code each time it changes.

ReAct (Reason + Act)

A pattern for building agents, from a 2022 research paper. The LLM alternates between reasoning ("I need today's weather; I should call the weather tool"), acting (calling the tool), and observing the result, repeating until it can answer. Older LangChain code wired this loop up by hand; create_agent in v1 builds the same model ⇄ tools loop for you.

Docstrings and type hints

A docstring is the text in triple quotes right under a Python function's definition, describing what it does: """Get the weather for a city.""". Type hints like city: str and -> str state what types go in and come out. LangChain turns a function's name, docstring and type hints into a tool description the LLM can read, so a clear docstring directly affects how well the agent picks and uses the tool.

Python decorators

A decorator is the @something line written just above a function. It wraps the function to add behaviour without changing its code: @tool above def get_weather(...) takes the function and returns a LangChain tool object built from it (name, arguments, docstring, plus the function to run).

Coroutines (async functions)

A coroutine is a function defined with async def. Instead of blocking while it waits (for an API, a database, a file), it can pause with await and let other work run in the meantime. LangChain tools can be either normal functions or coroutines; async tools are useful when an agent calls slow external services.

Reasoning models

Some LLMs (Qwen3, DeepSeek-R1, OpenAI's o-series and GPT-5, among others) are trained to "think" before answering: they first produce a chain of reasoning ("the user wants the weather; I should call get_weather"), then the actual reply. Some APIs return that reasoning separately, which is why a response can include a reasoning section alongside the tool call. It usually improves decisions on multi-step tasks, at the cost of extra tokens and time.

Pydantic

A popular Python library for describing data with classes and type hints, and validating it. You write class Movie(BaseModel): year: int; when you create a Movie, Pydantic checks the values, converts what it safely can (the string "2010" becomes the integer 2010), and raises a ValidationError for anything it can't. A Pydantic model can also be turned into a JSON schema, which is how LangChain describes the expected output format to the LLM. float | None means "a float or nothing"; giving it a default of None makes the field optional.

PII (personally identifiable information)

Any data that can identify a specific person: names, email addresses, phone numbers, home addresses, ID or card numbers. AI apps often need to detect PII and mask or block it, so it isn't stored in logs, sent to an external LLM provider, or repeated back to the wrong user. "PII detection" middleware does this automatically.

Checkpointers and thread IDs

An agent forgets everything between calls unless its state is saved. A checkpointer (from LangGraph) saves the conversation after each step; InMemorySaver keeps it in RAM (lost when the program stops), while database- backed checkpointers keep it permanently. Each conversation is stored under a thread ID passed in config={"configurable": {"thread_id": "..."}}: the same ID continues the same conversation, and a new ID starts a fresh one, which is how one agent serves many users separately.

In-memory database

A database that keeps its data in RAM instead of on disk. Very fast, but the data is lost when the program stops, unless it's saved somewhere first.

Encoding (UTF-8)

Computers store text as numbers. An encoding is the rulebook for which numbers mean which characters. UTF-8 is the standard one today and covers every language (₹, é, हिन्दी, emoji). If a file is read with the wrong encoding, special characters come out garbled (like Ã© instead of é) or the read fails. That's why the loaders pass encoding="utf-8".

Glob pattern

A simple way to describe file names using wildcards:

PatternMatches
*.txtAny .txt file in this folder only
**/*.txtAny .txt file in this folder and every folder inside it
report_*.pdfreport_2024.pdf, report_q1.pdf, …

* means "any characters", ** means "any number of folders". The course calls it a regular expression, but a glob is simpler: regular expressions are a more powerful (and more complex) pattern language.

OCR (Optical Character Recognition)

Reading text out of an image by recognising the shapes of letters. A scanned PDF page is just a picture, so a normal PDF loader finds no text on it; OCR is what turns that picture back into text.

Multimodal model

An AI model that understands more than one kind of input (text and images, and sometimes audio or video). Google Gemini is one. For PDFs, you can give it a page image, chart or table and ask it to describe or extract what's there, which goes beyond plain OCR.

Unstructured (the library)

An open-source Python library that reads many file types (Word, PDF, HTML, emails, PowerPoint, …) and breaks them into typed elements: Title, NarrativeText, ListItem, Table, and so on. LangChain's Unstructured…Loader classes are wrappers around it. It's thorough but heavy, which is why it's slower than simple loaders.

sentence-transformers

A Python library that runs embedding models from Hugging Face on your own machine, for free. You give it sentences; it gives back vectors.

pypdf

A Python library that opens PDF files and pulls the text out of each page.

Dot product, magnitude and cosine similarity

The course gives the cosine similarity formula, (A · B) / (‖A‖ × ‖B‖), but not the maths behind it:

  • Dot product (A · B): multiply the two vectors number by number and add the results. Big when both vectors are high on the same features.
  • Magnitude (‖A‖): the length of the vector: square each number, add them up, take the square root.
  • Dividing by the magnitudes removes the effect of length, so what's left measures only the angle between the two vectors, i.e. whether they point in the same direction. The result runs from −1 to 1; 1 means the same direction.
