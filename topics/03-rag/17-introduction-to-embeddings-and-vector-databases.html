Section 4 · Lesson 17

Embeddings and Vector Databases

The next step after chunking: turn each chunk into a vector with an embedding model and store it in a vector database. This lesson explains what an embedding is, and why searching embeddings finds meaning rather than exact words.

Traditional databases: exact match

A database holds cat, dog, kitten, puppy. Search for cat and a traditional (SQL or NoSQL) database returns only cat: it looks for an exact match.

SELECT * FROM employee WHERE name = 'Krish';

Only the record whose name equals 'Krish' comes back. However complex the query, the match is exact.

What an embedding is

An embedding turns text into a vector: a list of numbers that represents its meaning. Models can't work with words directly, only with numbers.

"Apple" might become [0.2, 0.7, 0.1, …]. The vector database stores each vector as a record with an ID, so you know which text it came from. (Embeddings are an NLP idea; the course assumes the basics.)

Vector databases: similar meaning

Store the same four words as vectors and search for cat again: now you get cat and kitten.

Embedding models are deep learning models trained on huge amounts of text, so that similar meanings get similar vectors:

WordVector (example)
cat[0.2, 0.3, 0.4]
kitten[0.2, 0.4, 0.3]

The vectors are close, so the vector database, which returns whatever is closest to the query's vector, finds kitten too.

What the numbers mean

Each number can be read as a feature: how strongly the text relates to some property. With three made-up features:

MovieActionComedySuspense
Iron Man0.950.20.6
Hulk0.960.40.7
Sherlock Holmes0.60.750.9

Iron Man is the vector [0.95, 0.2, 0.6]. (Real models don't use named features like "action"; this is only to show the idea.)

Measuring closeness: cosine similarity

You just watched Iron Man on Netflix. Should it recommend Hulk or Sherlock Holmes next?

cosine similarity = (A · B) / (‖A‖ × ‖B‖)

Cosine similarity compares the direction of two vectors: the dot product divided by the product of their lengths. The higher the result, the more similar.

Iron Man and Hulk sit almost on top of each other; Sherlock Holmes is far away. Netflix recommends Hulk.

Similar-meaning search = find the vectors closest to the query's vector.

The vectors come from embedding models: paid ones from OpenAI or open-source ones from Hugging Face.

Takeaways

  • Traditional databases match exactly; vector databases match meaning.
  • An embedding is a vector representing text; similar meanings get similar vectors.
  • Cosine similarity measures how close two vectors are; the closest are the best matches.
