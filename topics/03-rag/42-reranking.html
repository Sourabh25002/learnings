Section 7 · Lesson 42

Reranking

Hybrid search improves which documents come back. Reranking fixes their order, so the most relevant ones are on top when they reach the LLM.

Definition

Reranking is a second-stage filtering step: a fast retriever (BM25, FAISS or hybrid) fetches the top-k documents, then a slower, more accurate model (a cross-encoder or an LLM) rescores and reorders them by relevance to the query.

Why a second stage is more accurate

The retriever compares vectors computed separately for the query and each document: fast, but coarse. A reranker reads the query and a document together, so it can judge relevance much better, but it's too slow to run on the whole collection. Hence fast retrieval first, careful reordering of the top few second.

An LLM reranker

A prompt like "Here is the query and the top-k documents; order them by relevance." Documents 1, 2, 3, 4, 5 might come back as:

New position12345
Document52143

Reranking doesn't fetch new documents; it puts the retrieved ones in the right order, so the best context comes first.

Takeaways

  • Three stages: retrieval → reranking → generation.
  • Fast first, accurate second: a cheap retriever, then a cross-encoder or LLM.
