Section 6 · Lesson 37

RAG Pipeline with a Semantic Chunker

The chunking code turned into a reusable class, then used as the splitting step of a full RAG pipeline. Writing your own chunker lets you choose the threshold. 

import os
from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

from langchain_core.documents import Document
from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnableMap
from langchain.chat_models import init_chat_model

os.environ["GROQ_API_KEY"] = os.getenv("GROQ_API_KEY")

The chunker

class ThresholdSemanticChunker:
    def __init__(self, model_name="all-MiniLM-L6-v2", threshold=0.7):
        self.model = SentenceTransformer(model_name)   # embedding model
        self.threshold = threshold                     # similarity needed to merge

    def split(self, text: str):
        sentences = [s.strip() for s in text.split("\n") if s.strip()]
        embeddings = self.model.encode(sentences)

        chunks = []
        current_chunk = [sentences[0]]
        for i in range(1, len(sentences)):
            sim = cosine_similarity([embeddings[i - 1]], [embeddings[i]])[0][0]
            if sim >= self.threshold:
                current_chunk.append(sentences[i])
            else:
                chunks.append(" ".join(current_chunk))
                current_chunk = [sentences[i]]
        chunks.append(" ".join(current_chunk))
        return chunks

    def split_documents(self, docs):
        result = []
        for doc in docs:
            for chunk in self.split(doc.page_content):
                result.append(Document(page_content=chunk, metadata=doc.metadata))
        return result
  • Settings: the embedding model and the threshold, stored once when the chunker is created.
  • split(text): the algorithm from Lesson 36, returning chunk strings.
  • split_documents(docs): chunks each Document and keeps its metadata, just like LangChain's splitters, so it drops into the usual pipeline.
sample_text = """LangChain is a framework for building applications with LLMs.
LangChain provides modular abstractions to combine LLMs with tools like OpenAI and Pinecone.
You can create chains, agents, memory, and retrievers.
The Eiffel Tower is located in Paris.
France is a popular tourist destination."""

doc = Document(page_content=sample_text)          # metadata is empty here

chunker = ThresholdSemanticChunker(threshold=0.7)  # model_name keeps its default
chunks = chunker.split_documents([doc])

for c in chunks:
    print(c.page_content)

Same result as Lesson 36. Change the threshold or model to get a different chunker.

Store and retrieve

os.environ["OPENAI_API_KEY"] = os.getenv("OPENAI_API_KEY")
embedding = OpenAIEmbeddings()

vectorstore = FAISS.from_documents(chunks, embedding)
retriever = vectorstore.as_retriever()

The chunks are embedded with OpenAI (more accurate than the chunker's small model) into FAISS. Import OpenAIEmbeddings from langchain_openai to avoid a deprecation warning.

The chain

prompt = PromptTemplate.from_template("""Answer the question based on the following context:

{context}

Question: {question}""")

llm = init_chat_model("groq:gemma2-9b-it", temperature=0.4)

rag_chain = (
    RunnableMap({
        "context": lambda x: retriever.invoke(x["question"]),
        "question": lambda x: x["question"],
    })
    | prompt
    | llm
    | StrOutputParser()
)
  • RunnableMap (another name for RunnableParallel) builds context by running the retriever on the question, and passes the question along.
  • Temperature 0.4: slightly more varied answers than 0.2.
  • There's no format_docs step, so the raw Documents (metadata included) go into the prompt; formatting them gives cleaner context.
result = rag_chain.invoke({"question": "What is LangChain used for?"})
print(result)
# "According to the provided context, LangChain is a framework for building applications with LLMs."

The retriever searches the semantically separated chunks, and the answer comes from the matching one.

Takeaways

  • A custom chunker with split_documents slots in wherever a LangChain splitter would.
  • The rest of the pipeline is unchanged: store → retriever → prompt → LLM.
