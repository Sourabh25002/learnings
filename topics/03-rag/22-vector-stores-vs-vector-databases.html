Section 5 · Lesson 22

Vector Stores vs Vector Databases

Once chunks are embedded, the vectors need a home: a vector store or a vector database. People often treat them as the same thing; they aren't. Either one is then searched by similarity to find the chunks for a question.

The core difference

Vector store

A lightweight library for storing and searching vectors, running in memory or from a local file, wherever your code runs.

Vector database

A full database system built for vector data at scale, usually running as its own (often cloud) service.

Vector storeVector database
SearchSimple similarity search: the k nearest vectors to the query (KNN)Advanced search with metadata filters, plus full CRUD (create, read, update, delete)
ArchitectureIn memory or a local fileDistributed across machines: replication, sharding, high availability, scaling
ScaleUp to ~1 million vectorsBillions
SetupMinutesHours or days
CostAlmost freeMonthly, by storage, requests and reads/writes
Query speedMicrosecondsMilliseconds
DeploymentLocalCloud (AWS, Azure, GCP, or the provider's own)
Best forPrototypes, research, small appsProduction, enterprise data

Examples

Vector stores

FAISS (Facebook Research: "efficient similarity search and clustering of dense vectors"), Chroma, ScaNN, NMSLIB.

Vector databases

Pinecone, Qdrant (local or cloud), Milvus, Vespa, DataStax.

More on each in Background concepts. The course uses Chroma, FAISS, Astra DB (DataStax) and Pinecone.

When to use which

A vector store for a proof of concept, under 1 million vectors, the fastest search, a small budget or full control. A vector database for very large scale, production reliability and advanced querying.

Start with a vector store for prototyping and learning; move to a vector database when you need production scale, reliability and advanced querying.

Takeaways

  • Vector store: a library, local, simple nearest-neighbour search.
  • Vector database: a distributed system with filters, CRUD and scale.
  • Scale decides: ~1M vectors and below → store; billions → database.
