Section 9 · Lesson 51

Multimodal RAG

Real documents contain images: charts, diagrams, photos. Multimodal RAG retrieves over text and images, so "What does the chart on page 1 show?" can be answered.

What's new

Two questions the text-only pipeline never had to answer:

  • How do you embed an image so it can be stored and searched?
  • How does a text question find an image?

And the final LLM must be multimodal: trained on text and images, so it can read a chart (e.g. GPT-4.1, Gemini 2.5 Flash). Text-only models like GPT-3.5 can't.

CLIP: one embedding space for text and images

CLIP (Contrastive Language–Image Pre-training), an open-source OpenAI model on Hugging Face, was trained on ~400 million images paired with captions. It has a Vision Transformer for images and a text Transformer for text, both producing vectors in one shared space: "a bar chart of revenue" lands near an actual revenue chart.

Because text and images share one space, a text query can retrieve an image with ordinary similarity search.

The pipeline

  1. ExtractPull the text and images out of the PDF.
  2. Embed with CLIPText chunks and images, same model, same space.
  3. Keep images as base64Base64 (images written as plain text), the form the multimodal LLM accepts.
  4. StoreAll embeddings in one vector store (FAISS).
  5. SearchEmbed the query with CLIP; get back the closest text chunks and images.
  6. GenerateSend the text and images, in the LLM's message format, to a multimodal LLM.

(A common alternative, not covered here: have a multimodal LLM describe each image in words, then embed that description like any text chunk.)

Takeaways

  • Multimodal RAG = RAG over text and images, answered by a multimodal LLM.
  • CLIP puts text and images in one vector space, so text queries find images.
