Section 11 · Lesson 58

Message Types

Messages are the unit of conversation in LangChain: objects with a role (who it's from), content and optional metadata, carrying the state of a conversation. 

import os
from langchain.chat_models import init_chat_model

os.environ["GROQ_API_KEY"] = os.getenv("GROQ_API_KEY")
model = init_chat_model("groq:...")          # a Groq model (a reasoning model, judging by the outputs)

response = model.invoke("Please tell me what is artificial intelligence")
response            # AIMessage(content="...", ...)
response.content    # the model's answer

A plain string sent to a model counts as a human message; the reply is an AI message (response.content).

Text prompt vs message prompt

A text prompt (just a string) suits a single standalone request with no history. A message prompt (a list of messages) adds instructions and history:

TypeWhat it is
SystemMessageInstructions: how the model should behave
HumanMessageThe user's input
AIMessageThe model's reply, including any tool calls
ToolMessageThe result of a tool call
 
from langchain.messages import SystemMessage, HumanMessage, AIMessage

messages = [
    SystemMessage("You are a poetry expert"),
    HumanMessage("Write a poem on artificial intelligence"),
]
response = model.invoke(messages)
print(response.content)

Short vs detailed system messages

SystemMessage("You are a helpful coding assistant")
HumanMessage("How do I create a REST API?")

No language given → a generic answer about REST endpoints.

SystemMessage("""You are a senior Python developer
with expertise in web frameworks.
Always provide code examples and explain
your reasoning. Be concise but thorough
in your explanations.""")
HumanMessage("How do I create a REST API?")

→ a practical Python answer: Flask, code, tips like disabling debug mode in production.

The more context the system message gives, the more targeted the answer. (RAG prompts are system messages too: "answer only from the context…")

Metadata and history

human_msg = HumanMessage(
    content="Hello!",
    name="alice",        # identifies different users
    id="msg_123",        # unique ID, useful for tracing
)
model.invoke([human_msg])    # a friendly greeting back

name identifies the user; id helps tracing.

messages = [
    SystemMessage("You are a helpful assistant"),
    HumanMessage("Can you help me?"),
    AIMessage("I'd be happy to help you with that question."),   # written by hand
    HumanMessage("What is 2+2?"),
]
response = model.invoke(messages)
print(response.content)          # "2 + 2 is 4 ..." (with the model's reasoning)

A hand-written AIMessage in the list acts as earlier conversation; the model answers the latest question in that context.

response.usage_metadata
# {'input_tokens': ..., 'output_tokens': ..., 'total_tokens': ...}

Input, output and total tokens, for tracking cost.

Tool messages

from langchain.messages import AIMessage, ToolMessage, HumanMessage

ai_message = AIMessage(
    content=[],
    tool_calls=[{
        "name": "get_weather",
        "args": {"location": "San Francisco"},
        "id": "call_123",
    }],
)

weather_result = "Sunny, 72°F"          # hard-coded tool result
tool_message = ToolMessage(content=weather_result, tool_call_id="call_123")

messages = [
    HumanMessage("What's the weather in San Francisco?"),
    ai_message,          # the model asked for get_weather
    tool_message,        # the tool's answer
]
response = model.invoke(messages)        # answers using the tool result

An AI message with a tool call, then a ToolMessage with the result; its tool_call_id must match the call's id so the model knows which call it answers.

Takeaways

  • Four types: system (instructions), human, AI (incl. tool calls), tool (results).
  • String for one-off requests; a message list for instructions and history.
