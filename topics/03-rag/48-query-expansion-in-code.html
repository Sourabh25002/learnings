Section 8 · Lesson 48

Query Expansion in Code

A full pipeline: the question is expanded by an LLM, the expanded version retrieves the chunks, and the LLM answers the original question. The data is a long text about LangChain and CrewAI (another framework for agentic apps). 

from langchain.chains.combine_documents import create_stuff_documents_chain
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnableMap
from langchain_core.prompts import PromptTemplate
from langchain.chat_models import init_chat_model
from langchain_community.vectorstores import FAISS
from langchain_huggingface import HuggingFaceEmbeddings
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import TextLoader

Setup: chunks, store, retriever, LLM

# Step 1: load and split the data
loader = TextLoader("...")               # the LangChain + CrewAI text file
docs = loader.load()
splitter = RecursiveCharacterTextSplitter(chunk_size=..., chunk_overlap=...)
chunks = splitter.split_documents(docs)

# Step 2: vector store
embedding_model = HuggingFaceEmbeddings(model_name="all-MiniLM-L6-v2")
vectorstore = FAISS.from_documents(chunks, embedding_model)

# Step 3: MMR retriever
retriever = vectorstore.as_retriever(search_type="mmr", search_kwargs={"k": 5})
import os
from dotenv import load_dotenv

load_dotenv()
os.environ["OPENAI_API_KEY"] = os.getenv("OPENAI_API_KEY")

llm = init_chat_model("openai:o4-mini")

The usual pieces: split, FAISS with Hugging Face embeddings, an MMR retriever (top 5), and OpenAI's fast o4-mini (a Groq model works too).

The expansion chain

query_expansion_prompt = PromptTemplate.from_template("""You are a helpful assistant.
Expand the following query to improve document retrieval by adding relevant synonyms,
technical terms, and useful context.

Original query: "{query}"

Expanded query:""")

query_expansion_chain = query_expansion_prompt | llm | StrOutputParser()
query_expansion_chain.invoke({"query": "LangChain memory"})
Output

"LangChain memory OR LangChain memory management OR LangChain memory module OR persistent conversation memory OR embedding-based memory OR stateful chatbots OR session context persistence OR RAG memory store"

The pipeline

answer_prompt = PromptTemplate.from_template("""Answer the question based on the context below.

Context:
{context}

Question: {input}""")

document_chain = create_stuff_documents_chain(llm=llm, prompt=answer_prompt)

rag_pipeline = (
    RunnableMap({
        "input": lambda x: x["input"],
        "context": lambda x: retriever.invoke(
            query_expansion_chain.invoke({"query": x["input"]})
        ),
    })
    | document_chain
)

context is retrieved with the expanded query; input passes the original question to the answering prompt.

The expanded query is only for retrieval. The LLM still answers what the user actually asked.

Results

query = {"input": "What types of memory does LangChain support?"}

print(query_expansion_chain.invoke({"query": query["input"]}))   # see the expanded query
response = rag_pipeline.invoke(query)
print(response)
QuestionAnswer
What types of memory does LangChain support?"Two built-in memory classes: ConversationBufferMemory and ConversationSummaryMemory."
Does CrewAI support memory?"The snippets you have provided do not mention any memory features." The data has nothing on it, and the LLM says so rather than inventing.
CrewAI agentsExpanded with "agents OR bots OR assistants…"; the answer covers roles and semi-autonomous agents.
Cost

Each question now needs one extra LLM call before retrieval: more time, and more money with a paid model.

Takeaways

  • Expansion chain = prompt | LLM | parser, run before the retriever.
  • Retrieve with the expanded query, answer the original one.
