Section 7 · Lesson 39

Hybrid Search: Combining Dense and Sparse Retrieval

So far every search has been semantic. Hybrid search adds exact keyword matching and combines the two scores, for more accurate context.

Sparse retrieval: exact keywords

Turns text into a sparse vector: one slot per vocabulary word, almost all zero ("I want to have food" → [1, 0, 0, 0, 1, …]), using bag of words, TF-IDF or BM25. A document scores when it contains the query's words.

Dense retrieval: meaning

What we've used so far: dense embeddings compared with cosine similarity. Finds documents that say similar things, even in different words.

Hybrid search = exact search + semantic search. Each catches what the other misses.

The hybrid score

score_hybrid = α × score_dense + (1 − α) × score_sparse
  • score_dense: cosine similarity between the query's and the document's embeddings.
  • score_sparse: the TF-IDF or BM25 score: how well their words match.
  • α (0 to 1): the balance. 0.5 = equal weight; higher trusts meaning more, lower trusts keywords more.

Worked example

Query: "Building applications using LLMs". Documents: D1 "LangChain helps build LLM apps", D2 "Pinecone is used for vector search", D3 "The Eiffel Tower is in Paris". (Illustrative scores from the video.)

DocDenseSparseHybrid (α = 0.5)
D10.850.600.725
D20.400.200.30
D30.100.100.10

D1 is closest in meaning and shares words ("build", "LLM"), so it wins.

Correction to the video

The live arithmetic gives 0.775 for D1 and claims the scores sum to 1. The correct values are above; hybrid scores are independent per document.

Takeaways

  • Sparse = exact keywords (TF-IDF, BM25); dense = meaning (embeddings).
  • Hybrid score = α × dense + (1 − α) × sparse; rank by it.
