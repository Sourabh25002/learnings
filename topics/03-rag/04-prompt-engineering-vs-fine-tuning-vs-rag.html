Section 1 · Lesson 4

Prompt Engineering vs Fine-Tuning vs RAG

Three ways to make an LLM do what you need. Prompting changes the instructions, fine-tuning changes the model, RAG changes what the model gets to read.

Prompt engineering

Giving a base LLM (a model as it comes, e.g. GPT-4, Llama 3 or Gemini) a prompt (instructions) so it behaves the way you want.

Prompt (instruction)

Act as a chef and provide me a recipe.

Input (question)

Please tell me how to prepare pizza.

The LLM answers like a chef: a customised output. The prompt must be clear and structured. The model itself doesn't change: its parameters (the internal numbers it learned in training) stay untouched.

Pros

  • No technical expertise: plain English
  • Instant results
  • No training cost
  • Works with any LLM

Cons

  • Limited to the model's own knowledge; can't add new knowledge
  • Inconsistent: change the prompt or the model and results change (the biggest con)
  • Token limits (a cap on how much text the model handles) restrict complexity

Best for: small apps, generic tasks, quick prototypes. Not company-specific assistants.

Fine-tuning

Training the base LLM on new data (e.g. the company's), so its weights (its parameters) change permanently and it becomes a specialised model.

Example: a company assistant that should always greet and behave in the company's own way:

Hi, welcome to XYZ company. How may I help you?
  1. Prepare dataDomain-specific training data, e.g. the company's.
  2. TrainTrain the base LLM on it; the weights change.
  3. Specialised modelA fine-tuned LLM that keeps the new behaviour.

Pros

  • Deep, domain-specific knowledge (e.g. a legal expert)
  • Consistent behaviour; no prompting needed
  • Learns new styles and behaviours

Cons

  • Expensive: needs GPUs
  • Needs ML/AI expertise
  • Must be retrained to update

Best for: a specific style, high-volume consistent tasks, critical accuracy. (Techniques like LoRA and QLoRA exist; the course doesn't cover them.)

RAG

Teaching the model through retrieval: the base LLM stays as it is; for each query, relevant documents are retrieved from an external knowledge source, augmented and used to answer.

The knowledge source is usually a vector database (local or in the cloud), but can be an in-memory database, APIs or plain documents.

Pros

  • Up to date: just keep the data current
  • No training, so cost-effective
  • High accuracy (slightly below fine-tuning, improving as techniques improve)
  • Works with private data in your own databases

Cons

  • Needs infrastructure: a vector database and everything around it
  • Answers depend on retrieval quality
  • Context window (how much text the LLM can read at once) caps how much can be retrieved

Best for: most use cases, e.g. customer support and real-time or company data.
