Glossary

RAG
Retrieval-Augmented Generation: the AI looks up relevant information from an external source, enriches it, and uses it as context to generate its answer.
LLM
Large Language Model. Knows only what was in its training data, up to the date that data ends.
Retrieval
Fetching the content that matches the user's query from the vector database.
Augmentation
Enriching the retrieved content with metadata (source, date, …) before giving it to the LLM.
Generation
The LLM producing the output (often a summary) from the context it was given.
Context
The retrieved (and enriched) information handed to the LLM along with the question.
Vector database
A database that stores data (text, images, media, video) in the form of vectors (lists of numbers). Where the knowledge for RAG is kept.
Similarity search
How retrieval finds matching content in the vector database, using similarity metrics.
Metadata
Extra information attached to a piece of text, such as its source, page, author and date. In LangChain, a Document's metadata dictionary. Used for filtering, tracking sources, context and auditing.
Hallucination
When an LLM doesn't know something (it wasn't trained on that data) but guesses and makes up an answer anyway.
Text embeddings
Vectors (numbers) that represent text. Created by an embedding model and stored in a vector database.
ROI
Return on investment: how much value you get back for what you spend. Around 312% on average for RAG, per the course.
Source attribution
Every answer points to the source it came from. Important for compliance.
Base LLM
An LLM as it comes, e.g. GPT-4, Llama 3 or Gemini, before any fine-tuning.
Prompt engineering
Giving the base LLM structured instructions with clear context so it behaves a certain way. The model itself doesn't change.
Fine-tuning
Training a base LLM on new (e.g. company) data so its weights change permanently, creating a specialized model.
Weights
The model's internal parameters. Fine-tuning modifies them; prompting and RAG don't.
Token limit
The maximum amount of text a model can handle, which limits how complex a prompt can be.
Context window
How much context an LLM can take in at once. Limits how much retrieved content RAG can pass it. Varies by model.
Proprietary data
A company's private data. RAG can use it because it's stored in the company's own databases.
RAG pipeline
The full RAG system. Three core components: document ingestion, query processing, and generation.
Data ingestion pipeline
Reads data from its sources (PDF, CSV, websites, …), preprocesses it, and stores it in the vector database.
Chunk
A smaller part of a document. Data is split into chunks before being embedded.
Text splitter / document splitter
What divides documents into chunks.
Context size
How much content an LLM can take in as context. Differs per model; the reason data is chunked.
Embedding model
A model that converts text into vectors, e.g. from OpenAI or Hugging Face.
Cosine similarity / Euclidean distance
Techniques for finding stored vectors similar to the query's, i.e. similar text.
FAISS, ChromaDB, DataStax, Pinecone
Vector databases used in the course. Pinecone is one of the most commonly used.
Query processing phase
Embed the user's query, search the vector database for the most relevant chunks, and enrich them with metadata.
Retrieved results
The chunks of documents the search returns as the best match for the query. They become the LLM's context.
Generation phase
The original query plus the enriched context go to an LLM, which returns a summarised answer to the user.
Groq
A provider of many open-source LLMs, including Llama.
Parsing
Reading a file (PDF, Word, JSON, website, …) and getting its content out so it can be chunked.
LangChain
The Python library the course builds RAG pipelines with. Its integrations connect to many data sources.
LangGraph
A companion library to LangChain, also used in the course.
sentence-transformers
A library that converts text into vectors.
Document (LangChain)
The structure LangChain converts all loaded data into. Has two parts: page_content and metadata.
page_content
A Document's actual text, as a string. This is what gets embedded and searched.
Document loader
A LangChain library that reads a file (PDF, text, …) and returns Document objects.
Text splitters
LangChain classes that divide documents into chunks: RecursiveCharacterTextSplitter, CharacterTextSplitter, TokenTextSplitter.
TextLoader
LangChain loader that reads one text file into a list with one Document. Adds source (the file path) to metadata.
DirectoryLoader
LangChain loader that finds all matching files in a folder (via a glob pattern) and loads each with the loader class you give it.
glob
A file-matching pattern, e.g. **/*.txt = every .txt file in the folder and its sub-folders.
chunk_size / chunk_overlap
A splitter's maximum chunk size, and how much of one chunk may repeat at the start of the next.
Separator
Where a splitter is allowed to cut: e.g. "\n\n" (paragraphs), "\n" (lines), " " (words), "" (characters).
RecursiveCharacterTextSplitter
Tries a list of separators in order (paragraphs → lines → words → characters). The recommended default splitter.
split_text / split_documents
Splitter methods: the first takes a string and returns strings; the second takes Documents and returns Documents (keeping metadata).
PyPDFLoader
LangChain's common PDF loader. Returns one Document per page, with the page number and PDF info in metadata.
PyMuPDFLoader
A faster PDF loader with better text extraction and image support. Needs the pymupdf package.
Ligature
A single character that stands for two letters, like ﬁ for "fi". Common in PDFs; breaks search unless replaced.
create_documents
Splitter method that splits texts into chunks and returns them as Documents, attaching the given metadata to every chunk.
Docx2txtLoader
LangChain loader that reads a Word file as plain text into one Document.
UnstructuredWordDocumentLoader
LangChain loader for Word files. With mode="elements", returns one Document per structural element (title, paragraph, table), labelled in metadata['category'].
CSVLoader
LangChain loader that turns every CSV row into its own Document, with row in metadata.
UnstructuredExcelLoader
LangChain loader for Excel built on Unstructured. Handles complex Excel features; slow.
JSONLoader
LangChain loader for JSON. A jq_schema picks which part becomes Documents, e.g. .employees[] = one per employee.
jq_schema
A jq query passed to JSONLoader that selects records from the JSON.
SQLDatabase
LangChain utility that connects to a SQL database and shows its tables, DDL and sample rows. Doesn't produce Documents.
Relationship Document
A Document built from a JOIN across tables, so linked facts (e.g. who leads which project) are stored together.
Third-party tool
An external service the LLM can call, e.g. a web search API, to get information it wasn't trained on.
Embedding
A technique that turns text into a vector (a list of numbers) so a model can work with it. Similar meanings get similar vectors.
Exact match
How a traditional database (SQL, MySQL, NoSQL) searches: only records that match the condition exactly come back.
Feature representation
Another name for a vector representation: each number says how strongly the text relates to some feature (e.g. action, comedy, suspense).
Cosine similarity (formula)
(A · B) / (‖A‖ × ‖B‖): the dot product of two vectors divided by the product of their magnitudes. Higher means more similar.
Dimensions
How many numbers an embedding model puts in each vector, e.g. around 1,500 for an OpenAI model or 384 for a Hugging Face one. The dimensions have no names.
Cosine similarity (result)
Close to 1 = very similar, close to 0 = not related, close to −1 = opposite.
PCA
Principal component analysis: a dimensionality reduction technique that lets high-dimensional embeddings be plotted in 2D.
HuggingFaceEmbeddings
LangChain class (from langchain_huggingface) that loads any Hugging Face embedding model by its model_name. No API key needed.
all-MiniLM-L6-v2
A small, fast sentence-transformers model that turns a sentence into a 384-dimension vector. The course's default Hugging Face embedding model.
Sentence transformer
An embedding model that converts a whole sentence (or chunk) into one vector, rather than one vector per word.
embed_query / embed_documents
Embedding methods: the first takes one string and returns one vector; the second takes a list of strings and returns a list of vectors.
Semantic search
Searching by meaning rather than exact words. What embeddings stored in a vector database are used for.
OpenAIEmbeddings
LangChain class (from langchain_openai) that calls OpenAI's embedding models. Needs OPENAI_API_KEY set.
text-embedding-3-small / 3-large
OpenAI embedding models. 3-small: 1,536 dimensions, $0.02 per 1M tokens, general purpose. 3-large: 3,072 dimensions, $0.13 per 1M tokens, highest quality.
text-embedding-ada-002
OpenAI's previous-generation embedding model. For legacy applications; not recommended for new work.
.env / load_dotenv
A file that holds secrets like OPENAI_API_KEY, and the python-dotenv function that loads them into the program.
top_k
How many of the best-matching results a search returns, e.g. the top 3 documents by similarity score.
Vector store
A lightweight library or tool for storing and searching vectors, running in memory or from a local file. Simple k-nearest-neighbour search; best for prototypes under ~1 million vectors. E.g. FAISS, Chroma.
Vector database (vs store)
A fully featured, distributed database system for vector data at scale (billions of vectors), with filters, metadata queries and CRUD. E.g. Pinecone, Qdrant, Milvus.
k nearest neighbours
The k stored vectors closest to a query vector. What a vector store's similarity search returns.
CRUD
Create, read, update, delete: the full set of database operations a vector database supports on its records.
ChromaDB
An open-source search and retrieval database for AI applications. Run locally, the course uses it as a vector store.
Chroma.from_documents
Creates a Chroma vector store from a list of Documents: embeds each chunk with the given embedding model and stores it in a named collection.
persist_directory
The local folder where Chroma saves the vector store, e.g. ./chroma_db.
Collection
A named set of vectors inside Chroma (e.g. rag_collection); effectively the vector store's name.
similarity_search / similarity_search_with_score
Vector store methods that return the top k chunks most similar to a text query; the second also returns each chunk's score.
L2 (Euclidean) distance
Chroma's default score. A distance: lower = more similar, 0 = identical, typically 0 to 2.
Context augmentation
The pipeline step that combines the retrieved chunks with the query as context for the LLM.
ChatOpenAI
LangChain class (from langchain_openai) for OpenAI chat models, e.g. ChatOpenAI(model="gpt-3.5-turbo", temperature=0.2, max_tokens=500).
init_chat_model
Creates a chat model for any provider from a "provider:model" string, e.g. "openai:gpt-3.5-turbo" or "groq:…".
invoke
The method that runs a model or chain on an input. Replaces the deprecated predict.
Retriever / as_retriever
An interface to a vector store that only retrieves relevant chunks. vectorstore.as_retriever(search_kwargs={"k": 3}) creates one; needed to put a store into a chain.
ChatPromptTemplate
A prompt with placeholders like {context} and {input}, built from messages (from_messages) or one template string (from_template).
System prompt
The instruction message that tells the LLM how to behave, e.g. "answer from the retrieved context; if you don't know, say so".
create_stuff_documents_chain
Built-in chain that stuffs all retrieved chunks into the prompt's {context}, sends it to the LLM and returns the response.
create_retrieval_chain
Built-in chain that puts a retriever in front of a document chain. Invoked with {"input": ...}; returns input, context and answer.
LCEL
LangChain Expression Language: building a chain by connecting steps with the | (pipe) symbol, without helper functions.
RunnablePassthrough / RunnableParallel
LCEL building blocks: the first passes its input through unchanged (e.g. the question); the second runs stages in parallel.
StrOutputParser
The last step of a chain that returns the LLM's reply as a plain string.
add_documents
Vector store method that embeds new chunks with the store's embedding model and adds them to an existing store.
Conversational memory
Passing the previous conversation (chat history) into a RAG chain so follow-up questions like "What are its types?" are understood.
Standalone question
A question rewritten so it makes sense without the chat history, e.g. "its types" → the types of machine learning.
create_history_aware_retriever
Wraps a retriever so the LLM first rewrites the latest question into a standalone one using the chat history, then searches with it.
MessagesPlaceholder
A slot in a ChatPromptTemplate where a list of messages (the chat history) is inserted.
HumanMessage / AIMessage
Message objects for the chat history: the user's question and the LLM's answer.
ChatGroq
LangChain class (from langchain_groq) for models hosted on Groq. Needs GROQ_API_KEY.
FAISS (in code)
LangChain's FAISS vector store (needs the faiss-cpu package). Built with FAISS.from_documents; index.ntotal counts its vectors.
save_local / load_local
Save a FAISS store to a folder, and load it back (with the same embeddings and allow_dangerous_deserialization=True).
Metadata filter
A filter={"key": "value"} argument to a search that only considers chunks whose metadata matches.
search_type
An as_retriever option choosing how the retriever searches; "similarity" is plain similarity search.
RunnablePassthrough.assign
Passes a dictionary through a chain and adds a new key to it, e.g. context computed from x["input"].
Streaming / .stream()
Getting the LLM's answer in pieces as it's generated, instead of all at once with .invoke().
InMemoryVectorStore
LangChain's built-in vector store (langchain_core.vectorstores): vectors in a dictionary, cosine similarity with NumPy. Lost when the program stops.
Astra DB / AstraDBVectorStore
DataStax's serverless cloud vector database, and its LangChain class (langchain-astradb). Connects with an API endpoint and application token.
Pinecone index / PineconeVectorStore
A vector database in Pinecone is called an index. PineconeVectorStore(index, embedding) (langchain-pinecone) wraps it as a LangChain vector store.
dimensions (OpenAIEmbeddings)
Shortens text-embedding-3 vectors, e.g. dimensions=1024. Must match the vector database's dimension.
similarity_score_threshold
A retriever search_type that only returns results scoring at least score_threshold.
Semantic chunking
Splitting documents into chunks based on semantic similarity rather than size: adjacent sentences that are similar enough are merged into one chunk.
Document segmentation
The first step of semantic chunking: breaking a document into sentences or paragraphs.
Similarity threshold
The minimum similarity for two adjacent sentences to be merged into the same chunk (e.g. 0.7). Higher = tighter chunks.
SentenceTransformer.encode
Embeds a list of sentences with a sentence-transformers model directly, e.g. SentenceTransformer("all-MiniLM-L6-v2").encode(sentences).
Modular coding
Organising code into classes and methods (e.g. __init__, split, split_documents) so it can be reused and configured.
RunnableMap
Another name for RunnableParallel: builds a dictionary of inputs (e.g. context and question) for the next step of a chain.
PromptTemplate
A single-string prompt with placeholders, e.g. PromptTemplate.from_template("... {context} ... {question}").
SemanticChunker
LangChain's built-in semantic chunking (langchain_experimental.text_splitter). Takes an embedding model; uses a default threshold.
Hybrid search
Combining exact keyword search (sparse) with semantic search (dense) to retrieve more accurate context.
Sparse retrieval
Retrieval by exact keyword match, using sparse vectors from bag of words, TF-IDF or BM25.
Dense retrieval
Retrieval by meaning, using embeddings and cosine similarity.
TF-IDF / BM25
Keyword-scoring techniques that turn text into sparse vectors; a document scores higher when it contains the query's (rarer) words.
Hybrid score / α
α × score_dense + (1 − α) × score_sparse. α sets the weight; 0.5 = equal weight.
BM25Retriever
LangChain's local BM25 keyword retriever (langchain_community.retrievers, needs rank_bm25). Built with from_documents; .k sets top-k.
EnsembleRetriever
Combines several retrievers into one with weights, e.g. dense 0.7 + sparse 0.3. Merges results by weighted rank.
Recall
How many of the relevant documents a search actually finds. Hybrid search boosts it because each side catches what the other misses.
Reranking
A second-stage step after retrieval: a slower, more accurate model rescores and reorders the top-k documents by relevance to the query.
Cross-encoder
A model that reads the query and a document together and outputs a relevance score. Accurate but slow, so used for reranking a few documents.
LLM reranker
Reranking by prompting an LLM with the question and numbered documents and asking for the documents' order.
MMR (maximal marginal relevance)
A diversity-aware retrieval technique: picks documents relevant to the query but not redundant with those already picked. λ × sim(d, q) − (1 − λ) × max sim(d, selected).
λ (lambda, in MMR)
The relevance/diversity trade-off in MMR. 0.7 = 70% relevance, 30% diversity; 1 = plain similarity search.
search_type="mmr"
The as_retriever option that makes a retriever select documents with MMR instead of plain similarity.
fetch_k / lambda_mult
MMR retriever settings: how many similar candidates to fetch first (default 20), and λ (default 0.5).
Precision vs coverage
Getting only the most exact matches vs covering several aspects of a question. MMR favours coverage.
Query enhancement
Techniques that improve the user's query before retrieval, so better context is retrieved.
Query expansion
Reformulating a short or vague query with synonyms, technical terms and context, usually with a prompt + LLM chain. The expanded query is used for retrieval.
Knowledge base
The collection the retriever searches: in RAG, the vector store or vector database.
Query decomposition
Breaking a complex, multi-part question into simple sub-questions, each retrieved and answered separately, then combined.
Decomposer / synthesizer
In query decomposition: the step that splits the question (LLM + prompt, or regex), and the step that combines the sub-answers.
HyDE
Hypothetical Document Embeddings: an LLM writes a hypothetical answer to the query, and that answer's embedding is used to search the vector store.
HypotheticalDocumentEmbedder
LangChain's HyDE as an embedding function (langchain.chains.hyde.base). from_llm(llm, base_embeddings, prompt_key=... or custom_prompt=...).
WikipediaLoader
Document loader that fetches Wikipedia articles for a search query, e.g. WikipediaLoader(query="Steve Jobs", load_max_docs=5). Needs the wikipedia package.
Multimodal RAG
RAG over more than one kind of data, here text and images (e.g. charts inside PDFs).
Multimodal LLM
An LLM trained on both text and images, so it can answer questions about images, e.g. GPT-4.1, Gemini 2.5 Flash.
CLIP
Contrastive Language–Image Pre-training: an OpenAI model that embeds text and images into the same vector space (512 dimensions for clip-vit-base-patch32).
PyMuPDF (fitz)
A fast PDF library that extracts text (page.get_text()) and images (page.get_images(), doc.extract_image()).
FAISS.from_embeddings
Builds a FAISS store from precomputed (text, vector) pairs instead of embedding the text itself.
similarity_search_by_vector
Searches a vector store with a vector you provide, e.g. a CLIP-embedded query.
AI agent
An individual software program that performs a specific task with a degree of autonomy, following predefined rules. E.g. a customer service chatbot.
Agentic AI
A system where multiple AI agents collaborate and make decisions independently towards a larger goal, adapting from real-time data. E.g. a smart home system.
Perception, reasoning, action, learning
The four steps behind an agentic system's decisions: gather data, understand it, act on it, improve over time.
Human feedback in the loop
Keeping a person involved to review or correct an agentic workflow; a LangGraph concept covered later.
create_agent
LangChain v1's one-call way to build an agent: create_agent(model, tools, system_prompt). Invoked with {"messages": [...]}.
Tool (agent)
A function the agent's LLM can decide to call, e.g. a weather lookup. Its name, parameters and docstring tell the LLM when to use it.
Training cut-off
The date an LLM's training data ends. Anything newer (today's news, live weather) needs a tool.
Tool call / tool message
An AI message in which the model asks to run a tool with certain arguments, and the message carrying the tool's result back to the model.
model.stream
Returns an iterator of output chunks while the model is still generating; print chunk.text with end="", flush=True.
model.batch / max_concurrency
Sends a list of independent requests in parallel and returns a list of answers. config={"max_concurrency": n} caps how many run at once.
@tool
Decorator (langchain.tools) that turns a Python function into a LangChain tool, using its name, arguments and docstring as the schema.
bind_tools
Attaches tools to a model so it can request them (response.tool_calls). It doesn't run them.
Tool execution loop
Invoke the model → run each tool call → append the tool messages → invoke again for the final answer.
Text prompt vs message prompt
A plain string for a single standalone request, vs a list of message objects carrying instructions and conversation history.
SystemMessage / ToolMessage
The instruction telling the model how to behave, and the message carrying a tool's output (its tool_call_id matches the tool call's id).
usage_metadata
A response field with the input, output and total token counts of a model call.
Structured output
Making a model answer in a format matching a given schema (Pydantic, TypedDict or dataclass) so it's easy to parse and reuse.
with_structured_output
model.with_structured_output(Schema): returns a model whose responses are schema objects. include_raw=True also returns the raw message.
BaseModel / Field (Pydantic)
The base class for Pydantic schemas, and the helper that adds a description (and other settings) to each field.
TypedDict / Annotated
A schema type from Python's typing with no runtime validation (results are plain dicts). Annotated[type, ..., "description"] adds a description to a field.
model.profile
A chat model's capabilities: max input/output tokens, image/audio/video input, reasoning output, tool calling.
Dataclass
A Python class for holding data, made with @dataclass; no validation. Usable as a structured-output schema.
response_format / structured_response
create_agent(..., response_format=Schema) makes the agent's final answer follow a schema; it's returned in result["structured_response"].
Middleware
Code that runs at hooks inside an agent (before/after the agent or model, around tool calls) for logging, limits, retries, guardrails, summarization and more. Passed as create_agent(..., middleware=[...]).
Hook
A trigger point in the agent's loop where middleware can run.
SummarizationMiddleware
Built-in middleware that summarizes older conversation history when a trigger is reached, keeping recent messages per keep. Counts in messages, tokens or a fraction of the context window.
Checkpointer / thread_id
Saves an agent's conversation between calls (e.g. InMemorySaver()); config={"configurable": {"thread_id": ...}} picks which conversation.
HumanInTheLoopMiddleware
Pauses the agent before chosen tool calls for a human decision. interrupt_on={"tool": {"allowed_decisions": ["approve", "edit", "reject"]}}.
__interrupt__
Key in an agent's result when it has paused and is waiting for a human decision.
Command(resume=...)
From langgraph.types: resumes a paused agent with the human's decision, e.g. Command(resume={"decisions": [{"type": "approve"}]}), using the same thread_id.
