Section 8 · Lesson 49

Query Decomposition

Expansion makes a short query bigger; decomposition makes a complex query smaller: it splits a multi-part question into simple sub-questions, answers each, and combines the answers.

Why

One query that mixes several concepts retrieves chunks for some of them and misses the rest. Separate sub-questions each get their own targeted retrieval. It also allows multi-hop reasoning (answering in steps) and running the parts in parallel, e.g. in multi-agent systems.

How it works

What memory modules does LangChain support, and how are they different from CrewAI?
  1. SQ1: What memory modules does LangChain support?
  2. SQ2: What are CrewAI agents?
  3. SQ3: LangChain memory vs CrewAI agents: what's the difference?
  1. DecomposeWith an LLM and a prompt, or with regular expressions at punctuation (no LLM call).
  2. Retrieve and answer eachEvery sub-question gets its own top-k chunks and LLM answer.
  3. SynthesizeCombine the answers into the final one.

Advantage

More accurate context for every part of the question.

Disadvantage

Many LLM and retrieval calls: one to decompose, plus one of each per sub-question.

Implementation

Same setup as Lesson 48.

decomposition_prompt = PromptTemplate.from_template("""You are an AI assistant.
Decompose the following complex question into 2 to 4 smaller sub-questions
for better document retrieval.

Question: "{question}"

Sub-questions:""")

decomposition_chain = decomposition_prompt | llm | StrOutputParser()

query = "How does LangChain use memory and agents compared to CrewAI?"
print(decomposition_chain.invoke({"question": query}))
# 1. What type of memory mechanisms does LangChain offer for its models?
# 2. ...
# 3. ...
# 4. ...
qa_prompt = PromptTemplate.from_template("""Use the context below to answer the question.

Context:
{context}

Question: {input}""")

qa_chain = create_stuff_documents_chain(llm=llm, prompt=qa_prompt)
def full_query_decomposition_rag_pipeline(user_query):
    # 1. Decompose into sub-questions
    sub_qs_text = decomposition_chain.invoke({"question": user_query})
    sub_questions = [
        q.strip("-•1234567890. ").strip()
        for q in sub_qs_text.split("\n")
        if q.strip()
    ]

    # 2–3. Retrieve and answer each sub-question
    results = []
    for subq in sub_questions:
        docs = retriever.invoke(subq)
        result = qa_chain.invoke({"input": subq, "context": docs})
        results.append(f"Q: {subq}\nA: {result}")

    # 4. Combine
    return "\n\n".join(results)

print(full_query_decomposition_rag_pipeline(query))

The decomposer returned 4 numbered sub-questions; the list markers are stripped, each sub-question is retrieved and answered, and the Q/A pairs are joined. The answer ends: "LangChain excels in information retrieval and planning, while CrewAI specializes in managing collaborative interactions."

Here "synthesizing" is just joining; a fuller version would ask the LLM once more to merge the answers into one, at the cost of one more call.

Takeaways

  • Decompose → retrieve and answer each → synthesize.
  • More accurate, more expensive: use it when accuracy on complex questions matters.
