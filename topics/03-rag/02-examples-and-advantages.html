How RAG Works: Retrieval, Augmentation, Generation

The three letters of RAG are its three steps: find the relevant information (retrieval), enrich it (augmentation), and write the answer from it (generation).

Two ways to give an LLM outside knowledge

A tool

For today's news, connect the LLM to a third-party tool such as a web search API (a service it can send requests to). The LLM calls the tool, gets today's results and answers from them.

A knowledge base

For private data, store all the company's documents in advance in a vector database (a database that stores text as vectors, lists of numbers that capture meaning, so similar meanings can be found). Search it for each question. This is RAG.

R: Retrieval

Retrieval: fetching the content that matches the user's query from the vector database.

It uses a similarity search: finding the stored pieces whose meaning is closest to the question (several similarity metrics exist; covered later). What comes back becomes the context: the text handed to the LLM along with the question.

A: Augmentation

Augmentation: enriching the retrieved content with metadata (extra information about it, like its source and date) before it goes to the LLM.

A query about Tesla retrieves:

Revenue increased by 10%

On its own that's thin. With metadata attached:

text:   Revenue increased by 10%
source: Tesla annual report
date:   (the report's date)

Now the LLM knows where the fact came from and when it applies, so the answer is more accurate and can cite its source.

G: Generation

Generation: the LLM writes the output (often a summary) using the retrieved context, not just its own training.

This is what cuts hallucination: the answer is grounded in real text. It also means the answer is only as good as what was retrieved, which is why so much of RAG work is about retrieving better.

Data of any kind (text, images, media) is stored in the vector database as vectors, created by text embeddings (models that turn text into those number lists).

The full flow

  1. QueryThe user asks a question.
  2. RetrieveA similarity search on the vector database returns matching content.
  3. AugmentThe content is enriched with metadata.
  4. GenerateThe LLM answers from that context.

A full RAG architecture groups this into three phases: document ingestion (prepare and store the documents, done in advance), query processing and generation. Section 2 explains each one.

Takeaways

  • Retrieval: similarity search finds the matching content, which becomes the context.
  • Augmentation: metadata (source, date…) makes the context more useful.
  • Generation: the LLM answers from the context, so answers are grounded, and depend on good retrieval.
